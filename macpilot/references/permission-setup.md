# 시스템 설정 옆의 작은 권한 안내 패널

`mac_permission operation=setup` 또는 CLI `permission-setup`은 **macOS 권한 설정 창을 열고 그 옆에 앱 아이콘만 있는 88×88pt 패널을 표시**한다. 사용자가 패널의 MacPilot 아이콘을 실제 권한 목록으로 끌어 넣는다. 아이콘은 `NSWorkspace.icon(forFile:)`로 얻고 드래그에는 실행한 `MacPilot.app`의 실제 파일 URL을 사용한다. Finder를 열거나 Finder의 아이콘을 가져오지 않는다. 독립적인 큰 설정 대시보드는 만들지 않는다.

```sh
./scripts/macpilot permission-setup
./scripts/macpilot permission-setup screenCapture
./scripts/macpilot permission-setup automation com.apple.Safari
```

```json
{"kind":"all","operation":"setup","timeoutMs":10000}
```

현재 MCP가 구버전이면 설치된 스킬의 CLI를 사용한다. CLI 기본값과 앱을 Finder에서 실행했을 때의 기본값은 `all`이다. 아이콘 우클릭 메뉴의 이전·다음 권한으로 접근성·기기 제어 → 화면·시스템 오디오 → Safari Automation을 순서대로 설정한다. 우클릭 메뉴의 ‘다른 권한’으로 항목 하나를 열 수도 있다. 입력 모니터링·전체 디스크 접근은 일반 제어의 기본 권한이 아니므로 명시적으로 선택한다.

## 직접 드래그와 선택적 자동 추가

기본 방식은 **사용자의 직접 드래그**다. 패널은 시스템 설정 창의 공개 WindowServer 좌표를 읽어 옆에 붙고 이동을 따라간다. 실제로 다른 프로세스의 NSWindow 자식으로 등록하는 것은 아니다. 설정 창이 숨겨지거나 다른 앱이 활성화되면 패널을 숨긴다. 처음 접근성이 없어도 이 안내와 직접 드래그를 사용할 수 있다. 설정 페이지 이름이 관찰되고 요청한 권한과 다르면 드래그 아이콘을 숨기고 해당 설정을 다시 열도록 안내한다.

미허용 항목에서는 앱 아이콘의 복사본과 잡는 손 모양이 설정 목록 방향으로 이동하는 짧은 시연을 최대 두 번 표시한다. 원래 아이콘은 고정되어 있으며 사용자가 잡으면 시연을 즉시 멈춘다. 우클릭의 ‘드래그 안내 다시 보기’로 다시 재생할 수 있다. ‘동작 줄이기’가 켜져 있으면 시연하지 않는다. 파일·붙여넣기·Automation처럼 앱 드래그를 지원하지 않는 항목에서는 시연하지 않는다.

시연은 입력을 받지 않는 투명 창으로 표시한다. 시스템 커서, 실제 드래그, 목록 등록이나 동의 상태를 바꾸지 않는다. 접근성 승인 전에는 설정 창의 공개 좌표로 방향만 안내하며, 시연 종점이 AX로 검증한 드롭 대상이라는 뜻은 아니다. 시스템 확인 창이 있거나 사용자가 다른 앱으로 전환하면 시연을 숨긴다.

‘자동으로 추가’는 사용자가 아이콘의 우클릭 메뉴에서 선택했을 때만 같은 패널 아이콘을 권한 목록으로 드래그한다. 접근성과 이벤트 전송 권한이 없으면 메뉴 항목을 비활성화한다. 공유 시스템 입력 잠금, 현재 프로세스 시작 ID, 소스·대상 창 위치와 가림, 권한 페이지와 드롭 목록을 검증한다. 창 이동·다른 앱 전환·보안 입력·취소가 발생하면 드래그를 취소한다. 화면 권한의 주 목록과 오디오 전용 목록을 구분한다. MacPilot 표시 항목이 이미 있으면 다시 드래그하지 않는다.

시스템 인증, 권한 스위치, 브라우저 자체 승인, macOS의 ‘종료 및 다시 열기’·‘나중에’ 선택은 **사용자가 직접 진행**한다. 자동 추가는 이 버튼을 누르지 않는다. 인증·재실행·일반 확인·드롭 결과 미확인을 구분하고 미확인 동작을 자동 반복하지 않는다. 다른 MCP·대화·전체 호스트를 재시작하지 않는다.

## 권한별 동작

| kind | macOS UI와 안내 |
| --- | --- |
| `accessibility` | 접근성·기기 제어 목록에 패널 아이콘 드래그 |
| `screenCapture` | 화면·시스템 오디오 목록에 드래그 |
| `postEvent` | 같은 접근성·기기 제어 목록 사용 |
| `inputMonitoring` | 선택적으로 입력 모니터링 목록에 드래그 |
| `fullDiskAccess` | 선택적으로 전체 디스크 접근 목록에 드래그 |
| `automation` | 대상 앱을 선택하고 우클릭 메뉴의 ‘macOS 승인 요청’으로 해당 앱의 macOS Apple Events 동의를 요청. 드래그 등록은 지원하지 않음 |
| `files` | 파일 및 폴더 시스템 설정을 열고 실제 파일 사용 시 요청되는 권한임을 안내. 드래그 목록 없음 |
| `clipboard` | 지원 OS의 붙여넣기 시스템 설정을 열고 실제 읽기 시 요청되는 권한임을 안내. 드래그 목록 없음 |

Automation 기본 대상은 `com.apple.Safari`다. `targetBundleID`, CLI 두 번째 인수, 아이콘 우클릭 메뉴의 ‘대상 앱 선택…’으로 바꿀 수 있다. ‘다시 확인’은 Automation 동의를 새로 요청하지 않는다. Safari 개발자 설정·Chromium 확장·사이트 권한은 macOS TCC와 다르며 [브라우저 개발자 설정](browser-developer-settings.md)과 [작업별 워크플로](workflows.md)를 따른다.

## 결과와 검사 범위

`permission_setup_launch_accepted`는 안내 앱 실행 요청 수락이다. 툴팁·VoiceOver의 상태는 **안내 앱 프로세스**의 사전 검사다. 기존 MCP의 권한은 사용자가 승인한 뒤 현재 MCP의 `mac_doctor`로 별도 확인한다. 전체 디스크 접근·파일·붙여넣기는 일반 권한 사전 검사 API가 없으므로 허용됐다고 추정하지 않는다.

드롭 수락은 목록 추가나 권한 승인을 보장하지 않는다. 자동 추가의 `registered`·`already_listed`는 시스템 설정에서 MacPilot 표시 이름을 확인한 결과다. 목록이 설치 경로나 코드 해시를 노출하지 않으므로 `rowIdentity=display_name_only`로 구분한다. Automation은 미실행·승인 필요·거부·알 수 없는 결과를 구분한다. 요청을 한 번 시도한 같은 항목은 안내 창 안에서 반복 요청하지 않고 설정 확인을 안내한다. 시간 초과 뒤에도 시스템 요청 창이 남아 있을 수 있다.

`mac_permission operation=request`는 접근성·화면 캡처·이벤트 전송·입력 모니터링의 기존 요청을 지원한다. `setup`·요청에는 전경을 사용할 수 있는 작업과 공유 입력 잠금이 필요하다. `taskID`를 지정하면 `preserveForeground=false`를 사용한다. raw SwiftPM 바이너리는 드래그 대상으로 쓰지 않으며 서명된 `bin/MacPilot.app`을 먼저 빌드한다. 앱 경로는 전용 드래그 pasteboard로만 전달하며 일반 클립보드와 TCC 데이터베이스는 수정하지 않는다.

평상시에는 실제 앱 아이콘 하나만 표시한다. 제목·설명·버튼은 상시 표시하지 않는다. 안내는 툴팁·VoiceOver로 제공하며, 추가 동작은 아이콘의 우클릭 메뉴에 둔다. [디자인 비교와 구현 근거](permission-design.md)를 참고한다.

최초 권한 상태의 실제 검증은 [무권한 검증](permission-validation.md)을 따른다. 권한 결과를 바꾸거나 기존 앱의 TCC 승인을 초기화하지 않는다.
