# 모델 선택과 넘기기

사용자가 설명한 작업을 보고 시작 모델과 effort를 추천한다. 사용자가 넘기기를 원하면 추천한 모델·effort로 서브에이전트나 백그라운드 세션을 띄워 지시를 넘긴다. 현재 세션의 모델은 직접 바꿀 수 없다(사용자가 `/model`, `/effort`로 바꾼다). 판단 기준은 claude.dev 블로그 "Which Claude model should you build with?"(2026-11-09)이다.

## 판단 순서

1. 작업이 무엇인지 파악한다. 정보가 부족해 추천이 갈리면 가장 갈리는 한 가지만 묻는다. 그 외에는 가정을 밝히고 바로 추천한다.
2. 아래 표에서 가장 가까운 유형을 고른다.
3. 상향·하향 신호를 확인해 한 단계 조정한다.
4. 넘기기가 요청됐거나 넘기는 편이 나으면 아래 "넘기기"를 따른다.
5. 아래 출력 형식으로 답한다.

## 유형별 시작점

| 작업 | 모델 | effort |
|---|---|---|
| 일상 개발·디버깅, 여러 PR에 걸친 기능 작업 | Opus 5.5 | medium → high |
| 분류·라우팅·태깅·대량 추출 | Haiku 5.5 | medium |
| 서브에이전트(파일 검색, 로그 읽기, 요약) | Haiku 5.5 또는 Sonnet 5.5 | 모델 기본값 |
| 채팅·대화형 세션 | Sonnet 5.5 (단순 대량 채팅은 Haiku 5.5) | low~medium |
| 범위가 분명한 코딩(버그 수정, 명세 기반 기능) | Sonnet 5.5 | medium → high |
| 일상 문서·슬라이드·스프레드시트 | Sonnet 5.5 | high (Claude Code는 medium) |
| 반복 실행하는 에이전트 작업(조사·리뷰·초안) | Sonnet 5.5 | medium |
| 컴퓨터 사용·비전 중심 긴 루프 | Opus 5.5 | medium |
| 대규모 리팩터링·마이그레이션, 아키텍처 설계, 다수 서브에이전트 지휘 | Fable 5.2 | medium → high |
| 딥 리서치, 과학·정량 분석 | Fable 5.2 | medium → high |
| 모르겠음 | Opus 5.5 | medium |

## 조정 신호

상향(한 단계 위 모델 또는 effort):
- 명세는 명확하지만 마이그레이션·성능 최적화처럼 본질적으로 어려운 작업 → Sonnet 대신 Opus, 큰 규모면 Fable
- 복잡한 재무 모델, 방대한 자료를 종합하는 문서 → 문서류라도 Opus 5.5
- Opus 5.5가 `high`에서도 부족, 또는 오래 무인으로 도는 작업 → Fable 5.2
- Opus 5.5를 `high`보다 위(xhigh·max)로 올리려는 경우 → 먼저 Fable 5.2 `high`와 비교. FrontierCode 2.0에서 Opus 5.5 `max`와 비슷한 점수(45.3% 대 45.5%)에 작업당 비용 약 절반

하향:
- 결과를 자동으로 검증할 수 있는 대량 작업 → 낮은 effort로 돌리고 실패분만 높은 effort로 재실행
- 사람이 기다리는 응답 → Sonnet 5.5 low~medium
- 실수를 쉽게 알아챌 수 있는 보조 작업 → Haiku/Sonnet 서브에이전트에 위임

주의:
- effort를 올려도 모델에 없는 지식이나 능력은 생기지 않는다. 능력 문제면 모델을 올린다.
- 모델이 부족할 때 순서: 자체 검증 수단(테스트·빌드·스크립트) 확인 → effort 한 단계 상승 → 한 단계 큰 모델(이전보다 낮은 effort로 시작)
- Haiku 5.5는 프롬프트가 100K를 넘으면 단가가 5배가 된다. 긴 프롬프트를 매번 쓰면 완료된 작업당 비용으로 Sonnet과 비교한다.
- 작업 중간에 현재 세션의 모델을 바꾸면 새 모델의 첫 턴이 대화 전체에 캐시 쓰기 요금을 낸다. 바꿀 때는 `/compact`나 요약과 함께 자연스러운 끊김 지점에서 바꾼다. 아래 단계 모델로 내려가면 이전 추론을 읽지 못하고, Fable 5.2에서는 어느 모델로 가도 사라진다. 요약한 지시로 새 세션에 넘기면 이 비용을 피한다.
- 같은 모델에서 더 빠른 응답이 필요하면 Claude API에서 Opus 5.5·Fable 5.2의 fast mode(프리미엄 가격)가 있다.
- 작은 모델은 결과를 검증할 수 있는 대량 작업에 강하고 긴 에이전트 루프에는 덜 적합하다.
- Fable 5.2와 Opus 5.5의 캐시 읽기 단가는 100만 토큰당 0.20달러로 같아, 캐시 비중이 큰 긴 세션에서는 격차가 줄어든다(캐시되지 않은 입력·출력은 Fable이 2배).
- Fable 5.2의 기본 effort는 API `high`, Claude Code `medium`이다. Opus 5.5는 `medium`, Sonnet 5.5는 API `high`(Claude Code `medium`), Haiku 5.5는 `medium`이다.

## effort별 비용 대비 효과 (Opus 5.5, SWE-bench Pro, `high` 기준)

| effort | 점수 | 비용 |
|---|---|---|
| `low` | 약 8점 낮음 | 약 1/3 |
| `medium` | 약 2.5점 낮음 | 약 70% |
| `xhigh` | 약 1.4점 높음 | 2.5배 |

## 가격 참고 (2026-11-09 기준, 100만 토큰당 입력/출력 달러, API 정가)

| 모델 | 입력 | 출력 |
|---|---|---|
| Haiku 5.5 | 0.10 (100K 초과 0.50) | 0.50 (100K 초과 2.50) |
| Sonnet 5.5 | 2 | 10 |
| Opus 5.5 | 4 | 20 |
| Fable 5.2 | 8 | 40 |

이 파일에는 달러 기호를 쓰지 않는다. 스킬 인수가 달러 기호 뒤 숫자 자리에 치환돼 가격이 깨진다.

## 넘기기

추천한 모델·effort로 작업을 실제로 맡긴다. 방식은 결과를 어디서 이어받는지로 고른다.

| 상황 | 방식 |
|---|---|
| 결과를 이 세션이 받아 이어간다(조사, 검토, 범위가 분명한 하위 작업) | 서브에이전트: Agent 도구에 `model`, `effort`를 넣는다 |
| 독립적으로 길게 돌거나 사용자가 그 세션과 직접 대화할 작업 | 백그라운드 세션: `claude --bg --model … --effort …` |
| 지금 대화의 맥락이 커서 요약으로는 손실이 크다 | 현재 세션 전환 안내: `/compact` 후 `/model`, `/effort` |

- 사용자가 "넘겨줘", "돌려줘", "맡겨"처럼 실행을 요청했으면 확인 없이 진행한다. 추천만 요청했으면 넘기기를 한 줄로 제안하고 답을 받은 뒤 진행한다.
- Fable 5.2, `xhigh`·`max`, 여러 세션을 동시에 띄우는 경우에는 실행 전 비용이 커진다는 점을 한 줄로 알린다.
- 지시문 작성법, 명령, 시작 확인, 보고 형식은 [references/handoff.md](references/handoff.md)를 읽고 따른다.

## 출력 형식

짧게 답한다.

- **추천**: 모델 · effort
- **근거**: 이 작업이 그 유형인 이유 1~2문장
- **올려야 할 신호**: 이 작업에서 모델이나 effort를 올려야 하는 구체적 조짐 1~2개
- **위임 가능한 부분**: 작은 모델 서브에이전트에 맡길 수 있는 하위 작업(없으면 생략)
- **넘기기**: 넘겼으면 방식·세션 이름과 열기 명령, 넘기지 않았으면 가능한 방식 한 줄 제안(필요 없으면 생략)

작업이 여러 단계로 나뉘면 단계별로 다른 모델을 추천하고 단계별로 넘겨도 된다. 가정을 둔 경우 그 가정을 한 줄로 밝힌다.
