# Simulator device window

`simulator {"action":"window","device":"<UDID>"}` opens the actual simulator framebuffer in a native AppKit window. The LCD and thin device body are opaque. Only the area outside the device and controls is transparent; preview opacity affects previews alone. There is no standard title bar or traffic-light buttons.

- **Move:** drag the visible grip/name/status capsule above the device. Its status comes from the booted device and available framebuffer; the runtime name supplies the OS version. Moving the capsule never sends touches. Only the attached sidebar follows the device; independent panels keep their positions. The complete window fits the destination display after a move.
- **Size and window lifecycle:** drag the visible lower-right grip outside the LCD, or choose 50/75/100% in the capsule’s **기기 메뉴**. The same menu offers center, minimize and close. Close does not shut down the simulator. Call `window` again to reopen; the Dock restores an existing LCD, including minimized windows. The menu bar/LCD menu also exposes each device menu.
- **Basic controls:** Home and Rotate use the existing simulator command queue. Fold is shown only for a foldable device. Its popover has a slider applied on release and closed/partially open/open presets (0/130/180°). The caption follows the actual hinge reading, including external changes. Rotation does not show an assumed success state. The next rotation follows the actual backend orientation readback; the Duo inner display reports different rotation axes from the cover, so its picker mapping is handled separately.
- **Capture:** the capture button calls the existing screenshot backend, selects the active display from a multi-display result and opens a JPEG save panel. “Saved” appears only after the write succeeds. Cancellation, missing images and write/backend errors remain visible. Advanced screenshot/guided screenshot results remain in the activity response panel.
- **Floating modules:** the main sidebar owns device information, basic controls, auxiliary input, folding, advanced tools and status. Drag a module header to detach it; drop it on the highlighted sidebar to rejoin it. Each module menu offers the same operations. The main toolbar can follow the device or move independently. Layouts are stored per device; **기본 배치** rejoins modules and restores an on-screen layout. Drafts and action targets stay with the original control views.
- **Side tools:** Lock, Mac keyboard input on/off, touch marker visibility, and advanced tools. Keyboard toggling controls forwarding of Mac keys; it does not pretend to toggle the iOS software keyboard. Touch markers are viewer feedback and never enter screenshots.
- **Focus:** choose **집중 모드** in the device menu to hide the floating toolbar and all detached tool panels. The capsule and its menu stay visible for movement, restoration, sizing and closing. **⇧⌘T** continues to reveal advanced tools and exits focus mode. Draft fields survive these changes.

Clicks, drags, Option-drags, scroll and keys in the LCD retain the existing HID path. Chrome and transparent margins are separate hit targets. Manual contacts and held keys are released on focus changes, resizing, screen changes and close. Guest input coordinates use AppKit points regardless of Retina scale, with the simulator’s model mask and actual rotation. Reduce Transparency uses solid surrounding controls, Increase Contrast strengthens outlines, and Reduce Motion disables custom spring/fade feedback. No extra polling timer is added.

Preview restoration, per-display stacks, occlusion detection and device shutdown use the existing lifecycle. Build/log/web inspector features remain in their existing tools. For development verification without replacing a user installation, see `docs/mac-cu-device-window-validation.md` in the source repository. Development evidence is excluded from Plugin mirrors.

Open **설정…** from the menu bar, or **판단 API 설정…** from a device or toolbar menu, to configure OpenAI Decisions. The settings window uses the daemon environment and Keychain, never a previously connected client’s key. Its connection check sends only synthetic text; actual screen evidence is sent only for requested judgments.
