# Swift: SwiftLint를 먼저 사용한다

Swift가 대상에 포함될 때만 읽는다. SwiftLint는 코드 냄새 후보를 기계적으로 찾는 첫 조사 도구다. 모델이 같은 패턴을 전수 탐색하지 않게 한다. 진단은 설계 판단의 입력이며, SRP 위반이나 동작 보존의 증명은 아니다.

## 도구 발견과 필요한 설치

1. 가까운 `.swiftlint.yml`과 상속·중첩 설정, baseline, 제외 경로, CI 실행기와 버전 고정 방식을 찾는다. 기존 formatter도 확인한다. 생성 코드·외부 의존성의 제외 정책을 보존한다.
2. PATH의 도구만 보지 말고 저장소 실행기, 도구 관리자, 기존 패키지·플러그인이 제공하는 실행 경로를 확인한다. 설치된 실행 파일의 버전을 확인한다. 사용할 버전의 `lint --help` 등 실제 도움말로 지원 옵션을 확인한다.
3. 필요한 도구가 없으면 현재 요청과 저장소 권한에서 설치가 허용되는지 확인한다. 분석 전용 요청에서는 도구 부재와 진단 한계를 기록하고 가능한 소스 분석을 계속한다. 설치가 별도로 허용된 경우에만 도구를 설치한다. 이미 허용된 SwiftLint 설치는 재승인을 요청하지 않는다. 저장소의 설치 제한과 실행 환경 권한을 따르며, 추가 승인이 실제로 필요한 경우에만 이유를 설명하고 묻는다. 자동 스킬 선택 자체가 설치 권한을 만들지는 않는다.
4. 저장소가 정한 설치 방법과 고정 버전을 우선한다. 도구가 있다는 이유로 다른 버전을 사용하거나 기존 버전을 업그레이드하지 않는다. 고정 버전이 없고 기존 Homebrew를 사용할 수 있으면 공식 설치 방법인 `brew install swiftlint`를 사용할 수 있다. Homebrew가 제공하는 버전을 확인하고 기록한다. Homebrew 자체 설치는 별도 환경 변경이다.
5. Homebrew가 없거나 고정 버전이 필요하면 저장소의 도구 관리자 또는 공식 배포물에서 호환되는 경로를 선택한다. 해당 버전의 공식 설치 지침과 제공되는 무결성 확인 수단을 확인한다. 임의 다운로드 URL이나 지원 여부를 추측하지 않는다.
6. 설치 후 실행 경로·버전을 확인하고 저장소 설정을 사용해 진단을 실행한다. 설치 실패·버전 불일치·SourceKit/도구 체인 오류를 코드 위반과 구분해 기록한다. 막힌 설치를 다른 경로로 무작정 반복하지 말고 원인을 확인한다.

도구 설치 허용을 `Package.swift`, Xcode 프로젝트, 빌드 단계, 플러그인, 잠금 파일의 변경 허용으로 확대하지 않는다. 기존 실행기가 이런 파일을 변경하는지 먼저 확인한다. 이 스킬은 SwiftLint를 사용하기 위해 프로젝트 통합을 새로 추가하지 않는다.

## 진단으로 읽기 범위를 좁힌다

- 저장소의 검증된 명령을 우선한다. 수정 없는 lint를 먼저 실행하고, 가능한 구조화 출력(JSON 등)을 사용한다. 실제 버전이 지원하는 옵션만 사용한다.
- 명령의 작업 디렉터리, 설정 탐색, 중첩 설정과 제외 경로를 유지한다. 파일만 전달하면 설정 의미가 바뀌는지 확인한다. 안전한 좁은 실행이 없으면 정상 프로젝트 진단을 한 번 실행하고 결과를 범위별로 필터링한다.
- 전체 출력과 종료 코드를 보존한다. 모델에는 `파일, 위치, 규칙, 심각도, 메시지`와 규칙별 개수를 전달하고 필요한 실패 구간만 읽는다. 파싱 실패나 도구 오류를 "위반 0개"로 취급하지 않는다.
- 복잡도·중첩·함수/타입 크기·인자 수 등의 진단으로 우선순위를 정한다. 규칙 이름과 활성 여부는 실제 설정에서 확인한다. 크기 경고만으로 함수를 쪼개거나 같은 상태를 여러 파일로 흩뜨리지 않는다.
- 설정이 없으면 기본 규칙 진단을 참고 결과로 명시한다. 새 설정이나 baseline을 만들지 않고, 기본 규칙을 저장소의 합의된 정책으로 간주하지 않는다.
- 비활성 규칙이나 기존 baseline 때문에 관련 코드가 숨겨져 있다면 그 한계를 기록한다. 추가 진단이 필요할 때만 별도 임시 설정으로 참고 진단을 수행하고 공식 결과와 구분한다. 저장소의 규칙은 수정하지 않는다.
- 범위 확정 뒤에만 자동 수정을 고려한다. 대상과 옵션을 확인하고 별도 단계로 적용한 다음 diff와 재진단을 확인한다. formatter와 SwiftLint 수정이 충돌하면 저장소의 실행 순서를 따른다.

## Swift 동작 검증

책임 분리 시 접근 제어, 값/참조 의미, 객체 수명과 캡처, actor 격리, task 취소, 콜백 전달 문맥과 오류 전달을 관련 코드에서 확인한다. lint 성공은 컴파일·테스트 성공을 뜻하지 않는다. 빌드 정보가 필요한 분석은 저장소가 요구하고 유효한 입력을 확보할 수 있을 때만 실행한다. 플랫폼·기기·Release 검증은 저장소의 허용 범위를 따른다.

공식 설치·명령·설정 참고: [SwiftLint](https://github.com/realm/SwiftLint). 실행 시 저장소에 고정된 버전의 도움말과 문서를 우선한다.
