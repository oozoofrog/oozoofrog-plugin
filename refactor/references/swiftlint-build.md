# SwiftLint를 프로젝트 빌드에 통합한다

사용자가 SwiftLint 빌드 통합을 요청할 때 읽는다. 요청한 프로젝트의 빌드 파일을 수정하고 실행까지 확인한다. SwiftLint 진단 필수 조건과 실제 도구 설치 권한은 [Swift 지침](swift.md)을 따른다.

## 기존 빌드 구조에 연결한다

- `.xcodeproj`·`.xcworkspace`·`Package.swift`, XcodeGen·Tuist 등 생성 원본, 대상 target·scheme·configuration, 기존 SwiftLint 실행기·CI를 먼저 확인한다. 생성 프로젝트는 생성 원본을 수정하고 저장소 절차로 재생성한다. 같은 소스를 여러 target·스크립트·플러그인에서 중복 검사하지 않도록 현재 실행 경계를 확인한다.
- 명시된 프로젝트와 target 범위에서 구현한다. 대상이 하나로 명확하면 다시 묻지 않는다. 여러 앱·패키지 중 요청 대상을 결정할 수 없을 때만 필요한 범위를 질문한다. 통합만 요청한 경우 제품 로직을 리팩토링하지 않는다.
- 기존 도구 제공 방식·고정 버전·설정·baseline·제외 정책을 유지한다. 의존성·플러그인이 없으면 저장소 도구 체인과 호환되는 공식 배포 버전을 확인하고 저장소 관례에 따라 고정한다. 개인 머신의 절대 경로나 빌드마다 수행하는 `brew install`에 의존하지 않는다. 개발 환경과 CI의 실행 경로를 함께 확인한다.

## 통합 방식을 선택한다

- **SwiftPM:** 기존 플러그인이 있으면 재사용한다. 새로 연결할 때는 공식 SwiftLint 문서가 권장하는 `SwiftLintPlugins` 패키지와 `SwiftLintBuildToolPlugin`을 검토하고, 검사할 각 target에 연결한다. 해당 버전의 Swift tools·호스트·binary artifact 호환성을 확인하고 필요한 잠금 파일을 보존한다. command plugin을 등록한 것만으로 빌드 자동 실행을 주장하지 않는다.
- **Xcode build tool plugin:** 프로젝트 구조와 설정 탐색이 지원되면 패키지 의존성과 대상 target의 `Run Build Tool Plug-ins` 연결을 사용한다. 플러그인은 임의 `--config` 인수를 받지 않으므로 저장소 밖 설정이나 비표준 소스 경로가 있는지 먼저 확인한다. 기존 설정 의미를 바꿔 플러그인에 억지로 맞추지 않는다.
- **Xcode Run Script:** 기존 실행기를 유지하거나 플러그인으로 표현할 수 없는 설정·검사 범위에 사용한다. 공식 지침에 따라 보통 주 앱 target의 `Compile Sources` 다음에 배치한다. 저장소의 명시적 실행 경로와 작업 디렉터리·설정 인수를 사용하고 경로를 인용한다. Xcode의 비대화형 PATH가 터미널과 같다고 가정하지 않는다.
- 스크립트는 수정 없는 lint를 실행한다. 도구 부재·설정 오류·실행 실패의 종료 상태를 빌드에 전달한다. `|| true`, 경고 출력 후 성공 반환, 파이프라인의 종료 코드 손실로 필수 검사를 건너뛰지 않는다. 기존 위반 심각도·strict 정책을 유지하고 모든 경고를 새로 오류로 승격하지 않는다. 빌드 중 자동 수정은 추가하지 않는다.
- Run Script의 입력·설정 의존성 및 출력·증분 실행 정책을 명시한다. 소스·설정 변경 시 재검사되는지 확인한다. 매 빌드 실행이 필요한 경우 dependency analysis 설정을 그 정책에 맞춘다. 더미 output만 만들어 재검사를 누락하지 않는다.
- 플러그인 신뢰 확인과 script sandbox 제약을 구분한다. 설치·신뢰가 막히면 필요한 조치를 보고한다. 전역 Xcode 설정이나 CI 신뢰 검사를 자동으로 해제하지 않는다. sandbox 오류는 접근 경로·선언·플러그인 대안을 확인하고, 대상 target의 설정 변경이 필요한 경우 이유와 영향을 명시해 요청 범위에서 최소한으로 수정한다.

## 실제 빌드로 검증한다

1. 변경 전 기준선과 diff를 보존한다. 프로젝트 생성·의존성 해석 후, 요청 범위의 정상 빌드에서 SwiftLint의 실제 실행·버전·적용 설정·검사 대상과 종료 상태를 확인한다. 파일 연결이나 `swift package dump-package` 성공만으로 실행을 증명하지 않는다.
2. 증분 빌드에서 Swift 소스 또는 설정을 바꾸면 검사가 다시 실행되는지 확인한다. 의도한 캐시 사용과 검사 누락을 구분한다. 확인용 변경은 격리된 복사본이나 저장소의 fixture에서 수행한다.
3. 격리된 fixture에 실제 활성 규칙의 위반을 넣어 해당 진단과 저장소 정책에 따른 빌드 결과를 확인한다. 도구 부재·실행 실패도 빌드 실패로 전달되는지 통합 방식에 맞게 확인한다. 사용자 소스에 시험용 위반을 남기거나 기존 lint·CI 검사를 약화하지 않는다.
4. 재생성·잠금 파일과 최종 diff를 확인한다. 바뀐 빌드 경로의 필수 회귀 검사를 수행하고 전체 로그를 보존한다. 실제 빌드가 환경·신뢰·접근 권한에 막히면 구성 변경과 실행 미검증을 구분한다. 검증하지 않은 configuration·CI·플랫폼의 실행을 보장하지 않는다.

결과에는 수정한 프로젝트·빌드 파일, 선택 방식과 target 범위, 도구 버전·설정, 정상·증분·실패 전파 검증 결과, 미확인 환경과 필요한 다음 조치를 적는다.

공식 근거: [SwiftLint 설치와 빌드 통합](https://github.com/realm/SwiftLint#setup), [SwiftLintPlugins](https://github.com/SimplyDanny/SwiftLintPlugins). 적용 시 프로젝트에 고정한 버전의 문서와 도구 도움말을 확인한다.
