# One authorized source diagnostic cycle

Use `diagnostic_grant` only when a human has explicitly authorized a new, bounded evidence goal that requires instrumentation within an original failed task's retained source claims. It keeps the same task, owner, original artifacts, actual FAIL/count, consumed rework receipts, review allowance, budget/spent, reservations and history. It grants one diagnostic run, including when the original failure was already consumed by rework. It does not grant another correction attempt or extend review allowance. Never invent a FAIL, create a replacement task, release claims or choose another request ID to disguise retry.

Prepare an event containing `op`, stable `request_id`, exact `project` goal, canonical absolute `project_root` meaning the **state file's parent directory** (normally `.codex-team`), registered leader `requester`, original `task` and same execution `member`, full-state `source_sha256` using `harness.digest`, exact current `policy_hash`, `failed_review_digest`, `provenance_sha256`, nonempty `evidence_goal`, canonical absolute `modification_paths` contained within retained canonical claims, positive integer `max_reserve` within existing budget minus spent, `human_approval` from `ledger.evidence(path)`, and `approvals` path.

Compute the failure digest from `{'task': task_id, 'index': len(task['reviews'])-1, 'review': task['reviews'][-1]}`. Compute provenance with `harness.diagnostic_provenance(state, task_id)`, binding the full original task and its retained rework receipts. The latest review must be an actual fresh FAIL and task state must be `ready_for_review`. No active/uncertain runs, unresolved controls or in-flight handoffs may remain. Contract/checkpoint adoption is a separate administrative transition.

Retain the actual scoped human question and answer unchanged. Approval JSON contains `leader` and independent `reviewer`, each with registered `member`, `request_sha256` of the entire event excluding only `approvals`, and `approved`, `safe_boundary`, `all_current_obligations_retained`, `human_approval_verified`, `diagnostic_only` all true. The leader is the requester; runtime identity claims differ. Transactional capture copies full human and approval bytes into the canonical record. These are recorded attestations, not authenticated signatures or native session guarantees. Synthetic approval belongs only in isolated tests.

Submit through `harness --state ABS_STATE apply --event ABS_EVENT`. Full-state CAS, canonical state directory and exact contract must match. The grant increments revision and invalidates every ACK. Each affected participant reads its new packet and supplies its actual revision/epoch/digest ACK before continuation. All packet variants carry diagnostic scope, original failure/count, artifact/claim obligations, status and one-run bound; compact views do not remove this guard.

Begin the original task with the extra `diagnostic_request_id` and a positive reservation at most `max_reserve`. Normal owner, model, session, ACK, concurrency and project-budget gates still apply. The first committed begin consumes the entire cycle; even `not_executed` cannot reopen it. Canonical path aliases are rechecked; the harness records the approved scope but cannot intercept arbitrary OS writes. The managed stdio adapter remains read-only. Owner teams needing source writes must use their already authorized execution surface and stay within the narrower instrumentation paths.

The original task stays `ready_for_review` throughout. Finish with normal recorded terminal evidence and conservative usage accounting. Diagnostic `completed`, `failed` or `not_executed` closes the cycle and stores the diagnostic result separately; it does not replace original deliverable artifacts or validate coordinate content. `uncertain` retains unresolved status and blocks continuation until explicit observed-terminal reconciliation. Reconcile closes the consumed cycle; it never grants another run or accepts the original deliverable.

After any grant, normal begin, claim changes, release, reassignment, rework, handoff, review and acceptance of this task remain blocked, including session handoff prepare/transfer involving it. Other tasks and unrelated transfers retain their existing gates. A later correction requires a separately designed and justified authorized transition; this API deliberately stops after diagnosis.

Exact duplicate ID and payload is historical readback without mutation, even after terminal results. Conflicting payload and new IDs for the same original task/failure fail. On pre-rename failure old bytes remain; post-rename durability failure may already have committed. Read the canonical receipt before retry and reuse the exact original event. No project adoption, grant, ACK or business run occurs during software installation.
