# Method-bound observations and corrections

A diagnostic outcome records what finished; a completed run may still have insufficient observations. Preserve the original task, owner, claims, artifacts, actual FAIL and every prior result. No token allowance or total-attempt quota applies. Do not blindly replay an identical method, invent a failure or substitute a new task/ID for an unchanged attempt.

An initial `diagnostic_grant` binds exact project/state root, full-state CAS, current contract, original failed review/provenance, same owner, evidence goal and canonical instrumentation paths. Retain the already applicable human scope evidence plus independent leader/reviewer diagnostic-only approval; no reservation field exists. `begin` additionally names `diagnostic_request_id` and requires the actual fresh packet ACK. Active/uncertain work holds ownership. Supported terminal evidence closes the record; uncertainty requires observed reconciliation.

For a changed observation use `diagnostic_followup`: stable request ID, `previous_request_id`, exact project/root/state/contract, task/member, failed-review/provenance digests, evidence goal, modification paths, `prior_method`, `method`, root-cause and permission evidence, and independent approvals. The method has `collector` and `spec` file evidence, `input` with honest `kind` (`file` or `source_defined`) and evidence, plus observation `schema`. Fingerprints bind actual bytes and task/failure, excluding IDs/prose. Prior follow-up methods must match retained descriptors exactly. A first legacy seed links the actual predecessor run and terminal artifact to its retained method or explicitly linked executed-source manifest; missing input provenance needs an owner-supplied existing bound record, not invented measurement.

Root-cause JSON names `previous_run`, category `insufficient_observation` or `computation_failure`, reason and any permission denial. Current permission JSON must allow the exact paths. Denial is not a retry reason. Review flags bind `material_method_change`, `same_authorized_scope`, `permissions_current`, `prior_method_verified` and `diagnostic_only`, in addition to normal preservation/boundary approval. Hash differences do not establish semantic usefulness; the independent judgment and its limits are retained. The harness does not grant or intercept OS permissions.

After a closed diagnostic, legitimate correction uses the same method-bound `rework` form with `correction_authorization`: exact project/task/member/paths, kind `correction`, original authority-source evidence and a nonempty exact quote. The reviewer verifies `correction_authority_verified`; observation-only authority cannot promote itself. Keep the old closed grant unchanged, retain all FAILs and start assigned work under the same owner with a fresh ACK. Further materially different correction may continue with a retained predecessor method and actual terminal run; same fingerprint/new ID is rejected. Product acceptance still needs handoff of actual changed artifacts and a fresh independent PASS. No automatic PASS, failure reset or scope expansion follows from diagnosis.

Submit JSON through the normal atomic apply transaction. Exact duplicate ID/payload is readback; conflicting payload or stale CAS fails. Keep copied authority, terminal/method evidence and real project records private. Tests use openly labeled synthetic actors/approvals; they are not native project permission or ACK.

Pending work whose current permission evidence changes becomes inactive. An explicit `rework` with `renew_authorization: true` may renew the exact pending actor/scope/method using fresh permission, cause category `permission_renewal`, `pending_request`, original applicable authority and independent `authority_renewal_only` review. No collector mutation is needed to renew authority before any execution. A consumed execution cannot use renewal to replay the same method. Immutable copied authority/review corruption remains an integrity error. Ownership/claim changes invalidate old work authority; fresh applicable actor/scope binding is required before new execution.

When a closed observation is known `not_executed` because its environment failed before collector initialization, `diagnostic_permission_recovery` can append a separate submission grant. Keep the original closed record, method, owner, exact claims, task and FAIL unchanged. This permits submission for normal command-specific `exec_command` with `sandbox_permissions: require_escalated`; ordinary tool review still decides whether execution is allowed. Participant reviews grant no native permission. Explicit user, auto-review or access denial cannot use this path. Distinguish a sandbox initialization message from an actual policy denial using the retained terminal, linked initialization evidence and independent judgment.

The event uses normal project/root/current-contract, request/previous IDs, task/member/requester, failed-review/provenance, paths and goal fields, plus `source_sha256` and `source_raw_sha256` for parsed/raw CAS. `method` exactly matches the retained predecessor. `terminal_evidence` is the original run evidence, with run/diagnostic identity, `command_terminal: true`, explicit null `binary_path` and `collector_result_path`, collector/input hashes, log path/hash, and original `argv`, `environment` and `cwd`. `execution` is exactly those three original fields. A newly authored descriptor or changed numerical method cannot substitute for frozen evidence; the retained spec may be any file format.

`root_cause_evidence` JSON binds `previous_run`, `terminal_evidence`, `environment_evidence` (the linked log), category `environment_initialization_failure`, a reason, `collector_executed: false` and explicit false `user_denied`, `auto_review_denied`, `access_denied`. `submission_authorization` binds kind `permission_recovery_submission`, project/task/member/paths, applicable existing human `source` evidence and exact `quote`. Reuse unchanged applicable authorization; no repeated human confirmation is required. Current independent approvals add `environment_initialization_verified`, `known_not_executed`, `no_explicit_denial`, `existing_scope_verified`, `exact_execution_verified`, `permission_submission_only` and `diagnostic_only` to normal preservation/boundary flags. These are semantic actor judgments, not OS authentication.

One recovery successor may reference each predecessor, including one not yet begun. Fresh packet/ACK and `begin` with exact `execution` remain required; submission rechecks method/input, authority, failed review, terminal/log and approval freshness plus copied bindings. Denied/unknown native outcomes remain denied/unknown. After an uncertain save result, read the same stable request ID before acting: exact committed-event readback creates no transition or execution. Installation does not update a project's policy hash; existing schema-2 owners explicitly adopt the changed contract through `policy_refresh`, then obtain current review/ACKs.
