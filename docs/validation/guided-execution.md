# Guided Execution 검증 기록

## 0.6.0 (2026-11-11, macOS / Python 3.15.2 / Claude Code 2.1.322)

로컬 작업 트리 검증 기록입니다. 게시·CI·사용자 기기 설치·새 대화 노출은 별도로 확인합니다.

- 기록: `plan.requirements`와 `state.todos` 검사, `loop_control.py todo-add`·`todo-set` 전이(진행·완료는 작업이 running/passed일 때만, 제외는 사유 필요, plan digest와 작업 검사는 그대로), 요구사항·할 일이 없는 이전 실행의 호환을 테스트 90개로 확인했습니다.
- Mod: 세 번째 보기 '요구사항 할 일'(요구사항별 묶음, 진행 수, 제외 수, 요구사항 미지정 묶음, 빈 상태), 띠의 `할 일 n/m`, `/clear` 뒤 기록을 다시 읽는 것을 Mod 테스트 16개(모의 엔진)로 확인했습니다.
- 웹: '세션 작업'과 '요구사항 할 일' 탭을 점검용 기록으로 헤드리스 Chrome에서 1440px·600px·빈 상태로 캡처해 확인했습니다. 이 기능을 만든 실제 실행 기록으로 사용자 Chrome에서도 두 탭과, 작업 칩을 누르면 세션 작업 탭에서 그 작업이 선택되는 것을 확인했습니다.
- 배포 뒤 실제 세션(설치본 0.6.0, `/reload-plugins`)에서 `/guided-board` 요약이 `할 일 13/14`를 표시했고, 패널의 '요구사항 할 일' 보기와 프롬프트 위 띠는 사용자가 화면에서 확인했습니다. 창 캡처는 남기지 않았습니다.
- Claude 할 일 목록 반영: 임시 프로젝트의 실행 기록(요구사항 2개)으로 `claude -p`(설치본 0.6.0 스킬 문서)를 돌렸습니다. 프롬프트에는 반영 방법을 적지 않았습니다. 할 일 3개를 `todo-add`할 때마다 TaskCreate가 호출되었고, 각 항목은 subject가 할 일 제목, description이 요구사항과 작업 제목, metadata가 `{run, todo}`였습니다. `todo-set` in_progress·completed는 TaskUpdate의 같은 상태로, dropped는 deleted로 반영되었습니다. 마지막 TaskList 결과(#1 completed, #2 pending)가 `state.json`과 일치했습니다. 대화형 세션의 할 일 목록 표시와 TodoWrite만 있는 호스트는 확인하지 않았습니다.

## 0.5.0 (2026-11-11, macOS / Python 3.15.2 / Claude Code 2.1.322)

로컬 작업 트리 검증 기록입니다. 게시·CI·사용자 기기 설치·새 대화 노출은 별도로 확인합니다.

- 서버: `/api/file`은 관찰된 경로만 엽니다. 비밀로 보이는 파일·바이너리·심볼릭 링크·관찰되지 않은 경로·`/etc/hosts`는 거부합니다. `/api/explain`은 관찰된 명령만 받아 대기열에 넣고, 답을 캐시합니다. `/api/question`은 표시하고, 한 번만 답을 받고, 해결 상태로 바꿉니다. 이 동작을 테스트 87개로 확인했습니다.
- Mod: 대시보드에서 먼저 답하면 그 답이 도구 호출의 결과가 되고 터미널 대화창은 철회됩니다. 해결 상태는 `via: dashboard`로 기록됩니다. Haiku 설명 일괄 처리, path·command 전송도 Mod 테스트 13개(모의 엔진)로 확인했습니다.
- 웹: 점검용 기록과 Chrome DevTools의 실제 마우스 hover·클릭으로 다음 화면을 캡처해 확인했습니다. 질문 카드(선택지·직접 입력·보내기 후 전달 중, 서버 상태 answered), 명령 툴팁(설명 준비됨, 생성 중 표시), 퀵뷰 대화상자(경로·크기·수정 시각·줄 번호)입니다.
- 실제 세션(설치본 0.5.0, 사용자 Chrome, mac-cu 접근성 트리와 창 캡처)에서 세 기능을 확인했습니다. 작업 상세의 `파일 읽기 · lessons.md` 보기 버튼으로 퀵뷰가 열렸고, 전체 경로·80B·수정 시각·줄 번호가 실제 파일과 같았습니다. 명령 행에 마우스를 올리면 명령 원문과 실제 Haiku가 만든 한국어 설명이 툴팁으로 나왔습니다. 시험용 AskUserQuestion은 대시보드에 `CLAUDE 질문` 카드로 표시되었습니다. 대시보드에서 고른 답(`사과`)이 도구 결과로 돌아왔고, 카드는 `대시보드에서 답함: 사과`로 바뀌었습니다. 따라서 실제 엔진이 hook 답의 출력 스키마를 받아들입니다. AI 끄기 상태의 거절 응답과 실제 세션의 설명 생성 중 표시는 확인하지 않았습니다.
- `/clear` 뒤 `/guided-board`가 기록이 있는데도 `실행 기록 없음`을 표시하는 문제를 찾았습니다. Mod의 모듈 변수가 `/clear`로 비워진 세션 상태와 어긋난 것이 원인입니다. 수정은 Unreleased에 있습니다.

## 0.4.0 (2026-11-11, macOS / Python 3.15.2 / Claude Code 2.1.322)

로컬 작업 트리 검증 기록입니다. 게시·CI·사용자 기기 설치·새 대화 노출은 별도로 확인합니다.

- Mod `tool.call` 관찰과 작업 귀속(명시 `--task`, 작업에 묶인 서브에이전트, 유일한 진행 작업, 쓰기·읽기 범위, 그 밖은 세션)을 Mod 테스트 10개로 확인했습니다. 관찰된 호출은 바뀌지 않고 실행되며, 패널에는 진행 중 호출·최근 호출·경과·횟수가 표시됩니다.
- 서버 `/api/activity`는 헤더 토큰만 받고 최대 120건을 메모리에만 둡니다. 모르는 필드는 버리고 모르는 작업 ID는 세션으로 돌립니다. `/api/records`의 작업별 기록 타임라인·시작 시각·범위·증거 경로는 실제 `loop_control.py` 전이로 확인했습니다(테스트 84개).

- 실제 세션(사용자 Chrome, mac-cu 접근성 트리와 창 캡처)에서 확인했습니다. 진행 중인 작업 노드에 진행 중인 호출(`◌ 외부 도구 사용 Google Chrome`, 확인에 쓴 바로 그 호출), 경과 `12:11`, 배지 `24 ✗1`, 활동 레인 13건이 표시되었습니다. 끝난 작업 노드에는 그 작업 중에 한 마지막 호출이 남았습니다. 실제 Haiku 요약(토큰 1,866)도 표시되었습니다. 같은 열 안의 선행 선이 위쪽 노드 위로 휘어 그려지는 표시 문제가 있습니다. Mod를 다시 불러오면 이전 서버가 Claude Code 종료 때까지 남습니다.

### 실제 작은 프로젝트

재현 명령은 새 출력 디렉터리를 요구합니다.

```sh
python3 -B guided-execution/tests/test_project_scenario.py --output-dir /tmp/guided-notes-demo -v
```

테스트는 실제 임시 프로젝트와 Python CLI를 만들고 subprocess로 실행합니다. 단순히 상태 JSON의 문자열만 비교하지 않습니다.

1. JSON 내보내기의 Unicode 훼손과 기존 출력 덮어쓰기 검사 2개가 실제로 실패합니다.
2. 실행 시도를 시작한 뒤 생산자만 수정합니다. 변경된 소스·Python 실행기·검사 argv·통제된 환경의 fingerprint를 `set-revision`으로 기록합니다.
3. 실제 단위 검사와 문서화된 CLI 실행을 통과하고 원본 보존·덮어쓰기 거부를 확인합니다.
4. 미결정 검토 관문이 의존 작업 시작을 막고, 명시적으로 **SIMULATED fixture**라고 표기한 답변 뒤에만 열리는지 확인합니다. 거절은 관문을 열지 않습니다.
5. 재개가 시도·이력·증거를 유지하는지, 입력 변경 후 생산자와 후속 작업만 무효화되고 무관한 완료 작업은 유지되는지 확인합니다.
6. 실제 실패 세 번 후 시도 소진이 추가 시작을 막고 기존 로그가 보존되는지 확인합니다.

스크립트의 가상 답변은 실제 사용자 승인이나 사람이 답할 때까지 기다리는 UI 동작을 검증한 근거가 아닙니다. 파일 변경 감지와 적절한 검사 선택은 테스트의 호스트 역할이 수행합니다. helper가 자동으로 제품 변경을 탐지하거나 의미적 정확성을 증명하지 않습니다.

### 행동 관찰과 독립 검토

기존 0.1.1 스킬로 별도 작은 메모 프로젝트를 수행한 비교 기준 실행도 성공했습니다. 프로젝트 명령과 이전 Unicode 교훈을 읽어 실제 5개 검사와 CLI smoke를 통과했습니다. 평가자가 fixture도 만들었으므로 맹검 비교가 아니며, 새 지침의 정량적 우월성을 주장하지 않습니다. 0.2.0은 관련 탐색·재사용을 명시하고 상태 전이를 재현 가능한 명령으로 제공하는 변경입니다.

새 스킬의 별도 응답 수준 평가에서는 검색 기준이 미결정인 실제 CLI fixture를 조사하고 기존 검사 5개를 실행한 뒤, 추천안을 포함한 검색 기준 질문 1개를 했습니다. 제품 편집이나 의존 구현 없이 답변 대기 상태로 끝났습니다. 이는 한 상황의 관찰이며 모든 호스트에서 질문·대기를 강제한다는 뜻은 아닙니다.

독립 검토에서 보고서가 현재 증거만 검사하고 과거 시도의 변조 로그를 놓치는 문제가 재현되었습니다. 보고서도 상태 전이 도구와 같은 이력 무결성 검사를 거치도록 수정했고 회귀 검사를 추가했습니다.

### 시각화와 남은 한계

설계 참고 자료와 구체적인 반영·제외 범위는 [온톨로지 시각화 참고 자료](guided-execution-visual-references.md)에 정리했습니다. 공식 WebVOWL/VOWL, Neo4j Bloom, Observable D3, Cytoscape, React Flow 및 W3C 문서의 원칙을 참고했으며 라이브러리 코드나 브랜드 자산을 복제하지 않았습니다.

생성된 HTML의 구조, 악성 텍스트의 비활성 처리, 외부 리소스·실행 제어 부재, 원본 workspace 바이트 보존, 경로·덮어쓰기 보호를 검사했습니다. 0.2.1의 데스크톱·모바일 SVG를 Inkscape로 PNG 렌더링하여 노드·문자·화살표 배치를 육안 확인했습니다. 10개 직렬 작업은 글자가 축소되지 않고 가로 스크롤되며, 모바일은 360 단위 폭의 별도 세로 배치입니다. 독립 검토는 분기·여러 결정이 있는 최대 205개 노드의 경계·노드 비중첩도 검사했습니다. 브라우저에서는 생성 파일/로컬 서버에 접근하지 못했으므로 HTML 전체 화면·반응형 전환·실제 터치·스크린리더 동작은 육안 검수하지 못했습니다. 복잡한 그래프에서는 선이 교차할 수 있습니다. HTML은 오프라인 파일입니다.

0.2.1 독립 검토에서 재검증 대상의 과거 통과 증거를 현재 통과로 보이는 문제와 긴 그래프의 과도한 축소를 발견하여 수정하고 회귀 검사를 추가했습니다. 사용자 지정 문자열은 SVG 참조 식별자가 아닌 이스케이프된 텍스트로만 사용합니다. 명시되지 않은 에이전트·실제 재시작 이력이 없는 재시도는 만들지 않습니다. 제공 예제의 에이전트 역할은 화면 설명용 계획이며 실제 실행자라고 주장하지 않습니다. 예제 결정은 테스트용 모의 응답으로 명시되어 있습니다.

0.2.2는 짧은 순차 등장, 상태별 색 강조, 관계 방향을 따라가는 장식 흐름과 재시도 곡선 모션을 추가합니다. 원래의 노드·상태·관계는 바뀌지 않으며, 흐름은 실제 상태 전이나 과거 실행의 재생이 아닙니다. 화면의 연출 표시, 키보드로 접근할 수 있는 native checkbox, `prefers-reduced-motion` 정적 대체 규칙을 추가했습니다. 모션 끄기나 동작 줄이기는 효과와 장식 경로를 제거하되 기본 선·모든 노드를 남깁니다. 외부 리소스·JavaScript·실행 제어 기능은 추가하지 않았습니다.

모션 관련 테스트 5개를 먼저 실패시키고 구현 후 통과시켰습니다. 그래프·원본 기록 불변, 장식 경로의 의미 정보 중복 방지, 안전한 상태 CSS 분류, 모션 제어와 동작 줄이기 규칙을 정적으로 검사했습니다. 이번에도 지원 브라우저 경로로 화면을 열지 못했으므로 실제 시간에 따른 재생, checkbox 반복 조작, 키보드·스크린리더·OS 동작 줄이기의 브라우저 동작은 미검증입니다. 0.2.2 최종 데스크톱·모바일 SVG를 PNG로 렌더링해 노드·선·문자 경계를 확인했습니다. Inkscape는 CSS 애니메이션과 일부 그림자 필터를 지원하지 않으므로 이 검수는 정적 배치만 확인합니다. 배포 예제의 정적 SVG/PNG는 장식 모션을 끈 파생 미리보기이며 애니메이션 실행 증거가 아닙니다. 독립 검토에서 그래프 생성·배치·출력 보호 함수의 AST가 변경되지 않았고, 보고서 생성 전후 workspace 파일 11개의 바이트도 같았습니다.

0.2.3은 타입별 그라데이션 표면·관계 레일, 빛줄기와 이동점의 겹친 흐름, 상태 테두리 연출, 노드 주변 관계의 키보드/포인터 강조를 추가했습니다. 실제 기록의 좌표·상태·관계는 유지합니다. 큰 그래프에서는 장식 흐름과 테두리 효과를 각각 최대 24개로 제한하며 실제 노드·관계는 생략하지 않습니다. 키보드 초점이 남아 있는 포인터 위치보다 우선하고, 주변을 강조해도 다른 노드의 상태 글자·기본 관계선은 흐리게 하지 않습니다.

검토 중 전체 노드의 투명도를 낮추면 상태 문자의 명암 대비가 크게 떨어지는 문제를 발견해 표면·장식만 약화하도록 수정했습니다. 현대 CSS를 지원하지 않는 정적 렌더러에서 스타일 블록 전체가 무시되는 문제도 실제 검은 출력으로 확인했습니다. 단순한 기본 SVG 스타일·표현 속성과 고급 모션 스타일을 분리한 뒤 원본 SVG의 데스크톱·모바일 정적 렌더를 다시 확인했습니다. 지원되지 않는 장식은 숨겨져도 기본 내용은 남습니다. 독립 검토는 최대 122개 노드·354개 관계를 포함한 18개 레이아웃 상황에서 의미 정보·안전한 식별자·장식 상한을 확인했습니다. 검사한 제목/상태 색과 배경의 계산상 최소 명암비는 5.18:1이었으며 전체 접근성 인증을 뜻하지 않습니다. 이 정적 fallback 검수는 현대 브라우저의 실제 애니메이션·hover/focus·동작 줄이기 동작을 검증한 것은 아닙니다. 로컬 HTML을 재생할 지원 브라우저 환경을 확보하지 못했습니다.

Linux의 로컬 검증이며 macOS·Windows 실행은 확인하지 않았습니다. 실제 사람의 질문/대기/승인, 여러 호스트 연동, 백그라운드 자동 재개, 중단된 외부 작업 취소를 보장하지 않습니다. 단일 조정자가 기록하며 프로젝트의 실제 권한과 제품 결과는 호스트가 별도로 확인해야 합니다.

### 0.1.1 행동 평가

별도 에이전트에 다음 상황의 응답을 요청해 질문 선택과 대기 여부를 관찰했습니다. 제품 구현을 실행하는 검사가 아닌 응답 수준의 행동 검사입니다.

| 상황 | 관찰한 응답 |
| --- | --- |
| SwiftUI와 입력 항목은 정해졌지만 입력 흐름은 정해지지 않은 지출 입력 화면 | 0.1.0은 질문 없이 기본 흐름을 선택해 진행했습니다. 같은 입력의 0.1.1은 추천안을 포함한 사용 흐름 질문 1개를 하고 의존 구현 전에 답변을 기다렸습니다. |
| 이전에 답한 범위 그대로 작업 재개 | 같은 질문을 반복하지 않고 진행했으며 기존 질문 1개·1회 사용량을 유지했습니다. |
| 사용자가 질문 없이 판단해 진행하라고 명시적으로 위임 | 추가 질문 없이 위임 범위에서 진행했습니다. |
| 두 번째 질문 차례가 남은 대표 디자인 시안 검토 | 방향을 확대하기 전에 검토 질문을 하고 기다렸으며 요청 전체 사용량을 질문 2개·2회로 기록했습니다. |
| 기술 요소는 알려졌지만 첫 화면의 우선순위는 정해지지 않은 새 대시보드 | 에이전트의 현재 작업·상태와 막힘·사람의 주의가 필요한 작업 중 무엇을 우선할지 질문 1개와 추천안을 제시했습니다. 사용량 1개·1회를 기록하고 의존 UI 작업 전에 답변을 기다렸습니다. |

지출 입력 화면 사례는 수정된 질문 가이드에도 예시로 포함되어 있어 해당 실패의 회귀 확인으로 해석합니다. 새 대시보드 사례는 가이드에 예시로 넣지 않은 별도 상황입니다. 비교용 응답 중에는 디자인 검토에서 이미 질문 1개를 한 경우와 명시적으로 위임된 대시보드 작업에서 적절히 질문을 생략한 경우도 있었습니다. 따라서 기존 지침의 모든 경우가 실패했다거나 이번 변경이 정량적인 성능 향상을 보장한다고 주장하지 않습니다.

이 관찰은 모든 실행 환경의 질문·대기 동작을 강제하는 런타임 보장이나 실제 제품 구현 성공을 입증하지 않습니다. 보조 도구 검사 통과와 질문 정책에 대한 응답 관찰도 별도의 근거입니다.

### 0.1.0 행동 평가와 예제 실행 이력

초기 질문, 재개, 실행 환경 실패, 질문 예산 소진, 승인 대기라는 다섯 상황을 별도 에이전트로 검토했습니다. 비교용 기본 응답도 여러 요구를 이미 만족했으므로 이 관찰을 정량적인 성능 향상으로 주장하지 않습니다.

별도의 작은 메모 프로젝트에서는 당시 0.1.0 지침에 따라 질문 없이 작업 환경 생성, JSON 내보내기 구현, 사용법 문서화와 완료 기록을 수행했습니다. 원본 보존·덮어쓰기 거부·CLI 동작 등 9개 기능 검사와 실제 사용 명령이 통과했습니다. 이 예제는 개발 중 수용 검증이며, 예제의 소스와 9개 검사는 이 Plugin에 포함되지 않습니다. 이 이력은 0.1.1의 초기 질문 정책을 검증한 결과가 아닙니다.

### 배포 검증

```sh
python3 -B -m unittest discover -s scripts/tests -v
python3 -B scripts/sync_skill_mirrors.py --package guided-execution
git diff --check
```

0.1.1 변경 후 저장소 배포 검사 48개가 통과했습니다. 원본과 미러의 내용·파일 모드 일치를 확인했고, 미러 검사에서 추가 쓰기는 없었습니다. 변경한 배포 검사 파일의 Python 구문 검사와 공백 검사도 통과했습니다. 보조 도구의 26개 검사는 코드가 변경되지 않아 다시 실행하지 않았습니다.

배포 검사는 marketplace, manifest, 원본과 미러, 메타데이터와 문서 경로를 확인합니다. GitHub 게시, 사용자 기기에 설치·활성화, 새 대화의 스킬 노출, 실제 프로젝트의 성공은 각각 별도로 확인해야 합니다.

### 한계

`record_integrity_only`는 실제 실행을 증명하는 보안 경계가 아닙니다. 호스트가 현재 파일의 식별값을 대조하고 적절한 검사를 실제로 실행해야 합니다. 한 조정자만 작업 상태를 수정하며, 별도의 상시 실행 서버·스케줄러는 제공하지 않습니다. 이번 검증은 macOS·Windows의 실제 실행이나 모든 프로젝트 유형에 대한 성공을 입증하지 않습니다.
