# 지시를 작게 만들고 결과를 비교하는 방법

## 사람의 결정과 모델의 재량

| 사람이 정할 것 | 맡겨도 되는 것(현재 권한 안에서) |
|---|---|
| 목적, 독자, 최종 미적 선택, 중요도·트레이드오프 | 초안 구조, 일반적 구현 선택, 가역적 표현·배치 |
| 반드시 보존할 사실/기능, 예산, 공개·결제·계정 변경 승인 | 필요한 출처·도구 선택, 관련 검사 선정, 이미 승인된 수정 |
| 사용자 모델·서비스 선택, 팀 운영 전역 규칙 | 현재 팀 재사용, 실행 순서·작업 분담, 증거에 따른 수정 |

이 구분은 승인 경계를 바꾸지 않는다. "전부 알아서"도 모델·유료서비스 변경이나 외부 전달의 새 권한이 되지 않는다. 사람은 구현 단계를 전부 설계할 필요가 없고, 모델은 사용자 취향을 확정할 필요가 없다.

## 착수 전에 필요한 최소 확인

- **결과/입력:** 파일·화면·답변 중 무엇이며, 어떤 입력을 사용하나?
- **제약/재량:** 어떤 것은 보존하며, 어떤 선택은 맡기나?
- **출처/도구:** 정확성에 영향을 주는 현재 사실만 검증한다. 제품 사용법은 로컬 공식 자료 → 공식 문서, 기술 주장은 일차 연구/공식 자료를 사용한다. 확인일·대상 환경을 적는다.
- **완료/검증:** 관찰 가능한 기준을 2–3개 정하고 적합한 검사를 한 번 수행한다. 실패·새 변경·미해결 위험이 있을 때 검사를 추가한다. 모든 작업에 동일한 검수 단계를 강제하지 않는다.
- **예산/중단:** 사용자가 정한 한도를 우선한다. 예: 첫 초안 10분, 한 가지 과제, 관련 검사 한 번. 한도 초과 예상, 권한 거절, 핵심 자료 부재, 완료 기준 충돌 때 결과·근거·선택지를 전달한다. 이런 예시는 자동 결제나 전역 제한을 만들지 않는다.

## 작은 A/B 과제 — 설계만 제공, 아직 실행하지 않음

과제는 **같은 작은 HTML 대시보드 사본 하나를 개선해 실제 HTML 결과를 만드는 것**이다. 실제 화면이나 비공개 파일이 없으면 먼저 동일 입력 사본을 준비한다. 실제 데이터가 없으면 가상 데이터라고 표시한다. 공개 배포하지 않는다. 5–10분 첫 실습은 완료 기준 한 문장을 쓰는 연습이며, 아래 두 HTML 실행·검수까지 그 시간 안에 끝난다고 보장하지 않는다.

**A/B 공통 지시**

> 이 대시보드를 단순하고 세련되게 개선해줘. 핵심 행동은 [사전에 고른 한 가지]야. 기존 기능·정보는 유지하고 그 행동이 먼저 보이게 해줘. 세부 구현은 맡길게. 현재 요청의 팀·검수 규칙과 작업 우선순위를 지켜줘. 제공된 동일 예산과 도구 권한 안에서 결과 HTML과 검수 근거를 반환해줘.

**B에만 추가하는 한 문장**

> 완료는 핵심 행동의 식별, 기존 기능 보존, 잘림·겹침 없음으로 확인해줘.

- **변경 요인:** 명시적인 완료 기준의 추가만 비교한다. A/B의 목적·입력·보존·재량·예산·팀 규칙은 같다. 이는 원래 사용자 프롬프트 전문의 재현이 아니라 실험용 지시다.
- **고정:** 동일 입력 스냅샷, 모델 표시명/제공되는 버전·제품·reasoning 설정, 도구 접근, 시간/도구/비용 한도, 팀 규칙, 출력 형식과 평가표를 실행 전에 기록한다. 독립 문맥에 이전 결과를 주지 않으며 별도 출력 폴더를 쓴다. 순서를 정하고 기록한다. 기존 팀은 재사용하되 문맥을 분리한다. 사용자 모델을 바꾸지 않는다.
- **정확도:** 사전 기능·정보 보존 항목의 통과 수 ÷ 해당 점검 수. 항목이 없는 "정확도 100%"는 쓰지 않는다.
- **산출물 품질:** 핵심 행동의 식별(`action_identification`), 계층의 명료함(`hierarchy`), 잘림·겹침 없음(`layout_integrity`)을 각 0–2점으로 같은 평가표에서 채점한다. 0=실패, 1=일부 충족, 2=충족. 독립 검수에서 가능하면 A/B 라벨을 가린다. 취향 메모와 사실 오류를 합산하지 않는다.
- **효율:** 요청 시작→검수 결과 반환의 경과 초, 로그에서 관측된 도구 호출, 공개된 usage의 input/output tokens만 기록한다. 누락은 null/측정 불가이다. 호출 로그의 범위·실패·재시도와 다른 우선 작업 때문에 대기한 시간은 기록 메모로 남긴다. 벽시계 경과와 각 에이전트 시간 합계를 혼동하지 않는다. 금액은 확인된 해당 모델 요금·실제 사용량이 모두 있을 때만 산출한다. 중요한 누락·가정 오류와 사용자 수정 왕복은 별도 메모로 기록한다.
- **판정/중단:** 필수 조건 통과가 먼저다. 한 쌍은 실행 가능성을 보는 탐색이며 일반 성능 증명이 아니다. 후속 반복은 실익·예산이 있을 때만 한다. 한도/권한 경계/핵심 입력 부재/새 정보 없는 반복이면 현재 산출물과 남은 문제를 전달한다. 우선 작업과 충돌하면 현재 지시를 따른다. 입력 수정 전후 실행을 같은 조건으로 섞지 않는다.

문맥 분리와 기존 팀 재사용은 실험 때 확인할 실행 계획이다. 이번에 실제로 두 실행을 분리했거나 런타임이 누설을 막는다는 보장이 아니다. 해당 환경에서 독립 문맥을 확보할 수 없으면 그 한계를 남기고 비교 해석을 제한한다.

`scripts/compare_runs.py`는 두 개의 **실측 기록**을 검사하고 차이를 JSON으로 보여 준다. 자체적으로 모델을 호출하거나 시간을 재거나 품질을 채점하지 않는다. 누락값으로 효율 향상을 계산하지 않는다. [기록 서식](../assets/ab-record.template.json)은 A/B 실험 전 빈 서식이다. 빈 상태의 비교는 거부한다.
