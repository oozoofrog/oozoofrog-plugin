# Obsidian Projects

사용자가 지정한 보관함에서 기존 프로젝트 기록과 색인을 갱신한다. 이 스킬은 프로젝트 자동 재개·임의 삭제·앱/모델/외부 서비스 변경 권한을 주지 않는다.

## 기록 갱신

- 보관함과 적용 지침, 최신 홈·프로젝트 노트·근거·사용자 편집을 먼저 읽는다. 기존 색인을 재사용한다. 특정 보관함의 폴더 구조를 다른 보관함에 강요하지 않는다. 보관함별 합의는 해당 보관함의 접근 가능한 지침에서 확인한다.
- CLI·동명 링크·부분 절 갱신에는 [기존 보관함과 CLI 연결](references/cli-and-links.md)을 읽는다. 프로젝트는 기존 노트와 실제 저장소 경로로 식별한다.
- “첫 목록”, “정리”의 대상이 왼쪽 파일·폴더 목록인지 문서 본문의 목록인지 모호하면 변경 전에 대상을 확인한다. 이미 확인한 대상·승인 범위를 다시 묻지 않는다.
- 목표, 현재 상태, 근거와 확인 시각, 담당, 다음 행동과 대기 이유를 기존 형식에 맞게 연결한다. 없는 담당·진행률·승인·완료를 추정하지 않는다. 날짜별 오래된 실행 결과와 최신 상태를 구분한다.
- 구현/실행, 부분 완료, 검증 범위, 사용자 승인·수락은 별도로 기록한다. 코드나 검사 통과를 제품 전체 완료로 바꾸지 않는다. 오래됐거나 대기·미완료라는 이유로 목표를 취소하지 않는다. 재개 체크포인트와 실패/미검증 근거도 남긴다.

## 이동·정리

- 현재 필요한 목표·결정·검증·복구 증거·재사용 연구·사용 중인 초안은 보존한다. 중복·대체된 구버전·의미 없는 임시 잔여는 내용과 참조를 대조하여 구분하고, 판단이 모호한 자료만 보류한다. 임시 자료는 용도가 정해지면 프로젝트 등에 편입하고 불필요해지면 해당 정리 요청 범위에서 제거한다. 자동 만료·삭제를 만들지 않는다.
- 제거가 현재 요청 또는 기존 승인에 포함되는지 확인한다. 근거가 없는 삭제 후보를 임의 승인하지 않는다. 승인된 범위는 반복 확인하지 않고 수행한다. 혼합 노트에서는 해당 부분만 다루며 다른 프로젝트 정보와 사용자 메모를 보존한다.
- 이동·제거 전 복구 가능한 원문과 manifest를 남긴다. 원래/새 경로, 동작·이유·승인 근거, 원문 SHA256, 복구 위치·방법을 기록한다. 불필요한 파일은 보관함의 숨김 `.trash` 등 이번 작업 전용 복구 위치로 옮긴다. 영구 삭제·휴지통 비우기는 별도 요청 없이 하지 않는다.
- 쓰기 직전에 현재 내용/해시를 다시 확인한다. 읽은 뒤 생긴 사용자 편집을 덮어쓰지 말고 병합하거나 해당 파일 변경을 보류한다. 복원 시에도 새 파일·후속 편집을 덮어쓰지 않는다.
- 위키 링크, 상대 Markdown 링크와 첨부를 새 위치에 맞춘다. 동명 노트는 폴더 경로로 구분하고 모호한 링크를 임의 대상에 연결하지 않는다. 알려진 대시보드/작업 스크립트의 고정 경로를 제한적으로 검사한다. 권한 범위 밖 앱 코드 수정이 필요하면 영향을 보고하고 호환 사본으로 홈을 다시 어지럽히지 않는다. 역사적 영수증의 당시 경로·해시는 원문으로 보존하고 이동 명세로 현재 위치를 안내한다.

## 완료 확인

저장 후 파일을 다시 읽고 링크의 파일·절/블록·첨부 대상 존재, 동명 충돌, 중복 목록, 취소 작업의 활성 목록 잔존과 사용자 메모·미완료 목표 보존을 확인한다. 외부 URL·보관함 밖 추가 문서의 검사 범위는 구분한다. 범위 밖의 기존 깨진 링크는 별도로 보고한다.

시작 노트, 폴더/프로젝트 탐색, 이동·제거·보류 수와 이유, 복구 위치, 실제 검증과 남은 호환성 문제를 간결하게 전달한다. 앱에서 보여달라는 요청에는 허용된 지원 열기 경로를 사용하고 명령 성공·저장된 활성 노트·실제 화면 관측을 구분한다. 파일을 최상위에 두는 것과 탐색기에서 폴더보다 위에 표시하는 것은 다르다. 표시 순서를 확인하지 못했거나 설정 변경이 필요하면 그 한계를 보고하고 설정을 임의 변경하지 않는다. 다른 프로젝트·서버를 재개하거나 중단하지 않는다.
