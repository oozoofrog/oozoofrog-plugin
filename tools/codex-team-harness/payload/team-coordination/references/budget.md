# Explicit per-project budget changes

`budget_change` is an additive governance operation. It preserves every task, owner, claim, artifact, failed review/count, review limit, run, reservation, spent amount and prior history. It grants no execution permission. Initial/default project budget remains 100000. An explicitly approved project ceiling survives later contract migration; it is not inherited by another project.

Prepare an event with `op`, stable `request_id`, exact absolute `project_root` (canonical state directory), exact project goal in `project`, registered `requester` leader, full parsed-state `source_sha256`, current `policy_hash`, integer `expected_budget`/`new_budget`, nonempty `reason`, and `human_approval` captured through `ledger.evidence(path)`. Retain the human's actual scoped question and answer; do not replace an earlier denial or a failed review. The digest is `harness.digest`, not the raw JSON-file hash. `request_sha256` is the digest of the entire event excluding only `approvals`.

The `approvals` path names JSON with `leader` and `reviewer`: each has registered `member`, exact `request_sha256`, and `approved`, `safe_boundary`, `all_current_obligations_retained`, `human_approval_verified` all true. The leader must be the requester, and runtime identity claims must differ. These are recorded leader/reviewer attestations of existing human authorization, not cryptographic signatures or proof of a native session identity. Synthetic approvals belong only in tests.

Submit through `harness --state ABS_STATE apply --event ABS_EVENT`. All project active/uncertain runs, unresolved controls and in-flight handoffs block it. Full source CAS and the exact installed contract must match. If contract adoption is needed, perform the separately approved checkpoint/policy migration first; it cannot spend extra budget. The transaction copies full human and approval bytes with hashes into the canonical receipt, increases revision, and invalidates every old ACK. Each affected participant must read and actually ACK its new packet, which includes the effective budget and spent ledger, before any separately authorized reservation/continuation.

Exact duplicate request/payload is readback with original transition separate from current observation, including after later changes. Conflicting payload fails. Pre-rename failure retains old bytes; post-rename durability failure may already be committed. Read canonical receipt before retry; reuse the same ID and event. Never erase history, invent a FAIL, or pick a fresh ID to bypass an exhausted or uncertain operation. Source-code installation never changes any project's budget or adoption state.
