### Kickoff
**You own the map of intent. The user owns the decisions. Write no code.**

1. Read the inputs. Cite each input by URL plus commit, or by repo-relative path.
2. Do not create rule files or journal files without the user's consent (G3).
3. Write five parts: facts read, hypotheses (labeled Inferred), gaps, ideas and open questions. Put them in a file only at T2 or on request. Otherwise put them in the reply.
4. Settle each question that a run can answer with `playbooks/prototype.md`.
5. Ask the user-owned questions once, as one batch. Ask about the purpose first.
6. Record the answers. Strike rejected ideas through. Do not delete them.
7. Reread the result for contradictions, hidden questions and counterexamples.
8. Run `playbooks/wrap-up.md`.

**Report:** closed and open questions, prototypes built, rejected ideas, assumptions.
