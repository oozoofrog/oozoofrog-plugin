# Run a workflow on this host

Resolve paths from the physical directory of the SKILL.md you opened. Slash names in playbooks denote a skill ID. When giving the user an invocation, use the spelling for their host. A bundled skill ID refers to the sibling directory in this installation. If the host exposes another plugin with that ID, open the relative SKILL.md from this package. On remote workers, send the brief and necessary resources or identify their matching installed version. A parent machine's absolute path alone cannot identify a remote file.

Respect the user's and host's authority for delegation, scheduling, filesystem access, publishing, messages and irreversible actions. A playbook describes what an authorized operation requires. When a step requires an independent reviewer, different vendor, remote machine, secret input or persistent wake, report a missing capability and its impact. Continue independent steps. Never generate a verdict, URL, key, worker, or future wake as a substitute for a missing operation.

**Roles.** For every worker, read the settings using [configure-models](../../configure-models/SKILL.md). Explicit run choices take precedence over the saved role. The default inherits the session model. Respect the session's supported models, effort levels, limits and tool lifecycle. Tell the user which explicit choice is unavailable. Confine each writer to its assigned revision and output. For audit roles use enforced read-only access when offered, otherwise give a read-only brief and check the diff. Confirm actual model vendors before calling a review cross-vendor.

**Forge and artifacts.** Use the native PR/CI tool when the host requires it. Otherwise use the authenticated forge for the current repo. CLI examples describe equivalent operations. Honor the host watch completion event. For control-ui, control-cli and cleanup steps use the appropriate local app driver, CLI harness or diff inspection. Open and inspect the actual artifact. Use the host attachment or path format. Record unavailable evidence. Use configured scratch/output/cache roots, and keep resume notes on storage that survives the intended interruption.

**Authoring.** Inspect the host's project and personal catalogs before creating a skill. Resolve symlinks to identify the editable original. Update the existing skill in the requested scope. For a managed install, place an approved override in a discoverable writable scope and confirm which copy wins. Use a local skill authoring workflow when available. Otherwise create a directory with SKILL.md, name and description, validate its references and reopen it through discovery.
