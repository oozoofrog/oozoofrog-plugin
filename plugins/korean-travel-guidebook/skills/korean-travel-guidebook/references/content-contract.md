# 콘텐츠와 HTML 계약

## 전체 여행 → 첫날

먼저 각 날의 출발·귀가, 이동시간, 보행 범위, 고정 예약, 늦은 귀가 다음 이른 출발, 동행별 부담을 표로 평가한다. 문제가 있으면 방문 수·동선·숙소·교통을 조정하고 변경 이유를 짧게 적는다. 필수/선택/생략을 나누며 생략 시 시간·걸음 절감을 적는다. 나머지 날짜에 미정이 있어도 전체 틀을 점검한 뒤 첫날을 상세하게 완성한다.

각 날에는 브리핑, 시간표, 교통·관람·식사·앉는 휴식, 화장실, 준비물, 예약 확인, 날씨·피로 대안을 넣는다. 호텔 복도에서 귀가까지 포함하는 추정은 별도 표로 합산한다. 늦으면 무리하게 따라잡지 않고 선택 방문을 생략한다.

## 관광지 설명

익숙한 한국어 명칭 뒤에 현지명·영어명을 병기한다. 역사·인물·핵심 유물은 출처와 연결하고 역사적 사실과 전설을 분리한다. 규모 비교는 단위·기준·출처가 맞을 때만 한다. 옛이름은 현재 지명·시설과 연결한다. 이해를 돕는 한국사 동시대 비교, 쉬운 용어, 짧은 연표·관계도를 필요할 때 쓴다.

“어디에서 무엇을 볼지”가 명확해야 한다. 검증된 입구→관찰 지점→핵심 유물→앉는 휴식→출구 순서로 설명하고 층·전시실·번호·계단·엘리베이터 상태를 확인한다. 확인할 수 없는 번호와 관람 방향은 만들지 않는다.

사진은 실제 건물·유물·전시 상태와 정확히 일치하는지 본문을 열어 확인한다. 다른 복제품·다른 시대·다른 입구·생성 이미지를 실제 대상 사진처럼 쓰지 않는다. 관찰 캡션에 무엇을 봐야 하는지 적고 필요하면 번호를 표시한다. 원본, 저작자, 라이선스, 변경 여부, 필수 표시를 저장한다. 자료가 없으면 “사진 미확보”로 남긴다.

공식 지도가 있으면 이용조건을 확인한다. 자체 한국어 개념도는 “축척 없음·실제 지도 아님·길찾기용 아님”을 표시한다. 실제 좌표·거리·경로로 오인될 도식을 만들지 않는다. 공식 지도/검증 지도 링크를 별도로 둔다. 가짜 앱 화면과 가짜 길찾기는 금지한다.

## 마지막 현장 검색표

한국어·현지어·영어 이름, 정확한 입출구/역 출구/택시·셔틀 승하차점, 검증한 지도 링크와 확인일, 이름 복사, 직원에게 보여줄 문장을 포함한다. 포털 검색 링크는 목적지 검증 증거가 아니다. 미확인 항목에는 지도 링크를 만들지 말고 필요한 확인을 표시한다. 직원 문장은 예약·유료 서비스를 실행하는 지시가 아니라 도움 요청을 위한 문장이다.

## 디자인·오프라인

`assets/template.html`의 나눔고딕 우선 글꼴, 아이보리/베이지 배경과 흰 카드, 큰 글자와 여백을 유지한다. 표는 색 있는 헤더와 단색 본문 셀을 쓴다. 팁·주의 상자는 은은하게 하고 과한 둥근 모서리·캐릭터·장식을 피한다. 지도 식별색은 자유다.

모바일 첫 화면에는 제목, 핵심 동행/날짜, 오늘 판단, 보행 범위와 목차만 간결하게 둔다. 세부 역사·실전 절차·자료는 접거나 나누되 내용을 삭제하지 않는다. 모바일 목차는 줄바꿈하고 본문 흐름을 가리지 않게 한다. 사진 확대는 원본 링크/키보드로 대체 가능하게 한다. 복사 실패 시 선택 가능한 텍스트와 수동 복사 안내를 남긴다.

허용된 사진·폰트는 내장하고 라이선스를 보존한다. 외부 지도·최신 예약 페이지 등 네트워크가 필요한 기능을 명시한다. 오프라인에 지도가 저장됐다고 거짓말하지 않는다. HTML에 출처를 보존한다. 인쇄/PDF에서는 조사 출처 영역만 숨기되 저작권·라이선스의 필수 표시는 남긴다. PDF를 사용자가 요청하지 않으면 생성하지 않는다.

## 생성 도구 입력

`examples/fictional-input.json`은 구조 예시다. `fictional: true` 예시는 모든 여행지·수치가 가상임을 화면 상단에 표시한다. 실제 계획은 `fictional: false`와 실제 검증한 `checked` 날짜를 쓴다. 필드는 title, companions, summary, trip_review, days, practical, field_search, sources, attributions, unknowns 이다. 각 day의 today_decision에는 첫 화면에서 읽을 짧은 판단을 쓰고 briefing에는 충분한 설명을 보존한다. 텍스트는 HTML로 해석하지 않고 이스케이프한다. 이미지는 로컬 허가 파일만 데이터 URI로 내장한다. SVG는 정적 기본 도형·텍스트와 내부 #참조만 허용하며 script/style/foreignObject·외부 리소스·DTD를 거부한다. 허용하지 않는 SVG는 검증한 래스터 이미지로 준비한다. 링크는 http/https와 내부 anchor만 허용한다. 보행 low/high와 buffer_steps는 0 이상의 정수이며 bool·NaN·무한대·미상은 허용하지 않는다. 8천 보 초과에는 target_note로 이유를 명시한다. 지도는 map_verified=true, map_checked=YYYY-MM-DD, map_evidence=실제로 확인한 입출구 근거 URL이 있을 때만 검증 링크로 출력한다. 이 필드 작성은 사람/에이전트의 조사 책임이며 URL 형식만으로 검증되지 않는다. 이 생성기는 조사하거나 수치의 진실성·구간 누락 없음·요일·휴일·다음 날 출발 적합성을 보증하지 않는다.

## 검수

- 전체 일정의 동행자 부담 조정이 첫날 상세보다 먼저 있는가? 단위·합계·요일·현지 시간·예약 및 입출구 출처가 맞는가?
- 하루 목표 7~8천 보 및 불확실성을 포함한 범위 상단이 1만 보 미만인가? 필수/선택/생략의 걸음·시간 절감과 교통 대안을 검산했는가?
- 자료 본문, 최신성, 이미지 정확성·권리·필수 표기를 확인했는가? 접근 제한/검색요약은 확인 범위에 정직하게 반영했는가?
- `scripts/validate.py`로 HTML 구조·내부 링크·위험 URL·외부 리소스 의존을 확인한다. 외부 링크의 존재·목적지 일치는 별도 실제 접근으로 확인한다.
- 가능한 경우 허용된 headless 브라우저로 320/390/768/1440px에서 열고 overflow, 빈 이미지, JS 오류, 키보드 목차·details·복사 실패·확대 닫기, 네트워크 차단 상태, print media를 확인한다. GUI/ComputerUse 금지 요청에서는 GUI를 열지 않는다.
- 인쇄에서 상세가 사라지거나 표가 잘리지 않는지 확인한다. 긴 현지명·URL, 화면 확대 200%, 충분한 대비, 포커스 표시와 대체 텍스트를 점검한다.
- 검사 도구 부재 시 정적 검사 통과와 런타임/시각 미검증을 구분한다. 실제 스크린샷 검수 없이 시각 검증을 완료했다고 쓰지 않는다.
