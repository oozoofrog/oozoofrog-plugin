# Contract boundary

Contract JSON uses `schema: workcheck-contract/1`, a `project` label, absolute `runs` directory, optional absolute existing `note`, `inputs` list (`path`, pinned `sha256`), and `cases` mapping. Each case has an `argv` array and `scope`. `{out}` and `{case}` are the only substitutions. The adapter writes `{out}/result.json`. No shell interpolation or automatic install, retry, git or network action exists in the helper. Read argv before first use; a contract is code, not authorization.

Result JSON uses `schema: workcheck-result/1`, `scope`, nonempty `checks` (`id`, `status` PASS/FAIL/UNKNOWN, `reason`), and lists `evidence`, `unverified`, `next_actions`, `recovery`. `coverage` records what was actually observed. Evidence paths must resolve to real files inside this run or exact pinned inputs. Each receipt hashes them. PASS means only this contract's technical checks passed. Human acceptance is never inferred. Use FAIL for a reproduced defect even when the command ran successfully.

The helper checks missing/invalid/non-finite output (including exponent overflow), changed inputs, process failure, duplicate IDs and concurrent invocations; run validation failures get a receipt and stop. Invalid contracts/pins stop before a run begins. Pin identities are canonicalized consistently while the original paths remain in the contract. Notes must be disjoint from pinned inputs, contract, helper, evidence and the run output tree; symbolic/hard-link aliases are checked. Same-ID replay checks fingerprints and evidence hashes and does not rerun the adapter. A crash without a receipt is an incomplete run, not a pass or an implicit retry. Keep the directory and use a new run ID after inspection. Notes append paired markers per receipt; a partial marker stops rather than claiming a complete record. User content is preserved and a pre-append snapshot is kept. Concurrent non-cooperating edits cannot be fully serialized by an advisory file lock; append is used rather than whole-file replacement. Runtime/executable versions are recorded by project adapters; this is not a hermetic environment guarantee. Updating the helper changes its fingerprint; prior receipts remain historical and are not silently rerun or rewritten.

This is an original local implementation, not a copy or installation of those workflows. Their commit, parallel-agent, external-work and model-selection behavior is not adopted.
