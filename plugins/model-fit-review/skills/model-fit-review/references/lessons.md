# Lessons from the first run of this procedure

Each lesson is a failure that happened once and the rule that prevents it.

1. **Only human messages count.** In a T3 Code DB, many `role='user'` rows are delegation results, notices and messages from other sessions. Keep rows with `createdBy='user'` and `creationSource` in (`web`, `mobile`). In Claude Code logs, a filter that dropped only text starting with `<` kept most injected prompts: in a real review, most of a random sample of "human" messages were delegation briefs, relayed messages or resume notices. The log rule now has three layers, in this order (`mfrlib.prompt_kind`):
   - Entry fields: skip tool results, `isMeta`, `isSidechain`, `isCompactSummary` and `isVisibleInTranscriptOnly` entries. A prompt with `origin.kind` other than `human` (for example `peer`, `task-notification`), `turnOrigin` `task_notification` or `peer`, or `promptSource` `system` was not typed by a person. Fields such as `entrypoint`, `userType` and `promptSource: sdk` are the same for typed and injected prompts, so they cannot decide.
   - Prefix denylist (`mfrlib.INJECTED_PATTERNS`): `Delegated task node:`, `Act as the … sub-agent`, `Continue where you left off`, `Context handoff`, `[T3 Code: the agent in T3 thread …`, `This session is being continued from a previous conversation`, `Note: the T3 server restarted`, `Update on pull request #`, `<task-notification>`.
   - T3 authority: when a T3 DB is present, a log prompt in a session the DB knows counts as human only if it matches a T3 human message (procedure.md, "Joining T3 threads and logs"). Briefs without a denylisted prefix are caught only here.
   Injected prompts are not dropped: they start agent-initiated runs, so the timeline stays complete (lesson 2). Text starting with `<` is still skipped except slash-command wrappers, which become `/name args`. On the log-only path, report the 10-row precision check; English task briefs without a marking field remain the known gap.

2. **Count distinct runs; reactions need the whole timeline.** A run can carry several human messages, so counting (run, message) pairs inflates the run count, and many "next messages" are sent before the run finished. Messages sent while the run was going are steer, reported separately. A timeline built only from runs that carry a human message missed runs that a delegation result started: in a real review, a large share of the "reactions" followed such a run, so the user was reacting to the later result. The timeline now holds every completed run of the thread, any provider and initiator. The reaction to run R is the first human message after R completed, if no other run completed first; otherwise R is `superseded` and the message counts for the latest run that completed before it, when that run is a Claude run. `mfrlib.assign_reactions` encodes this; procedure.md lists the states.

3. **Session commands are not tasks.** `/compact`, `/clear`, `/reload-*`, `/mcp`, `/output-style` (and the same commands typed on a Korean keyboard layout) are excluded. A rule that dropped every slash message also dropped real tasks such as a slash-invoked skill with text and `/init`. `mfrlib.is_control` encodes the list.

4. **Calibrate classifiers before using their labels.** A follow-up classifier that met the 85 % gate against hand labels was used as data. A task-type classifier that missed the gate was used only for sampling, and no task-type rates were reported. Keep model names out of the items (`export_items.py` masks them). Calibrate on reaction items only: a steer message does not react to the reply shown next to it, and mixing the two lowered agreement. Hand labels must win over classifier labels whatever the order of the label files; once, a classifier file given after the hand file silently replaced hand labels and changed the episode count.

5. **A fix is not always the model's fault.** Fix reactions included the user's own mistaken facts, taste iteration on a design, results the user could not see yet, and process rules. Cards separate result fixes from method corrections.

6. **Pin everything a replay can read.** Replays that ran against today's machine read folders and a skill that the original episodes had created, so they saw the original answers. Only the replay whose inputs lived inside one pinned repository was valid. Use local clones with no remote, pinned to the commit before the episode, and check home config and sibling folders.

7. **The judge must check facts, and so must you.** A cross-vendor judge found that one candidate reported high-severity findings based on a feature that was disabled in the code. The main agent re-checked the decisive claims in the source. Without a different-vendor judge, report the missing independent verdict.

8. **Compare cost at equal context.** A replay in a fresh context used a small fraction of the tokens of the original step, which ran deep in a long thread and re-read its whole context on every call. The difference was context length, not the model.

9. **Practice design.** A pass mark the baseline already meets shows nothing; track over-picks instead. The guide between rounds cites only round-1 cards. When the misses fall on cards with `inferred` references while replay-backed cards are picked right, the data cannot tell whether the user over-picks or the references are too low. Record the evidence kind on every card and report the score per kind.

10. **Recurring corrections need mechanisms, not more text.** One rule ("ask questions as options") existed and kept being corrected; another ("answer in the user's language") existed and worked. A rule that applies to every reply stays in view; a rule that applies only at certain moments is missed. For the first kind, a dry-run check (Stop hook) on real turn endings measured catches and false alarms before install. A check must exempt lines that another standing instruction requires. Every change to global instructions, settings or hooks went through G2 with a backup.

11. **Move working files out of temporary storage first.** A session scratchpad can be cleared. Ask the user for the review directory before writing anything.

12. **Delete the DB snapshot at the end, with approval.** It can be several GB, and the scripts can rebuild everything from a fresh snapshot.

13. **Scope reactions to Claude runs; question answers are not reactions.** A T3 thread can mix providers. Count human messages attached to Claude runs separately from all human messages, and never use a message attached to a non-Claude run as a reaction to a Claude run (`other_provider`). Rows with `createdBy='user'` and `creationSource='server'` are the user's answers to an agent's question prompt. Decision: count them on their own line and never use them as a reaction, steer or request. Reason: they arrive while the run is still going, so they do not react to its result, and their text holds the agent's question plus the chosen option, so a classifier would read agent text as the user's words.

14. **Fix the period in the scripts.** Without `--since`/`--until`, a review extracted the whole history and filtered the window by hand, with different denominators on the two paths. Both extractors now take inclusive UTC dates and print the same count lines.
