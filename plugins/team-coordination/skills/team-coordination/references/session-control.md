# Session models and explicit handoff

Use `run.py session-control --help` from the verified bundle, or `Controller` in `scripts/session_control.py` with a long-lived official JSON-RPC connection. The default adapter is read-only; the explicit bounded-write handoff below is optional. This is not a native app setting hook or an OS execution interceptor.

Select an exact host, transport, controller and thread. Prefer a supported native app query/change tool when exposed. The CLI supports an explicitly supplied, authorized official `codex app-server proxy --sock` endpoint; it does not discover private sockets or credentials. `--transport owned-stdio` is an explicit standalone choice, never an automatic native fallback. Native app IDs may belong to another host/backend; not-found/unavailable stops the operation. Standalone ephemeral threads require the same long-lived connection; separate CLI invocations cannot resume them. Use a live native proxy for the multi-command flow, or the Controller API in one owned process. Do not treat a stored `notLoaded` record as current live settings.

`inspect --member NAME` uses metadata-only `thread/read`, with no history or resume. Model, reasoning effort and configured provider are observations of settings. Missing/null values remain unknown/unset. Runtime model/provider attestation stays unavailable; neither model text nor a provider label proves execution identity.

`change --member NAME --operation-id UNIQUE --model EXACT --effort EFFORT` validates the complete live catalog and role policy, records an intent, then returns `pending_turn_application` or `queued`. It does not claim server acceptance or immediate application. Reasoning effort is separate from model. Use `--owner-checkpoint FILE` for an external owner; an idle snapshot is not a lock.

`apply-change --member NAME --operation-id UNIQUE` explicitly sends one bounded nonimplementation configuration-check turn. Official `turn/start` model/effort apply to that turn and subsequent turns. The adapter records acceptance and re-queries settings after completion. A subsequent ordinary `turn --member NAME --task TASK --prompt FILE` sends neither model nor reasoning override, and every Normal turn explicitly sends `serviceTierForTurn: "default"` while omitting persistent `serviceTier`. It requires current context ACK/owner/permission gates, and records its completed turn ID. `verify --member NAME --operation-id UNIQUE --turn TURN_ID` requires that later controlled completed turn before reporting model/reasoning configuration verified. The explicit `verification_scope` distinguishes accepted per-turn Standard from unavailable persistent tier and provider execution. See [profiles](profiles.md) for the selected client protocol contract and field-specific tier semantics. Actual runtime provider/model remains unavailable. The observed installed CLI did not reliably apply model changes via resume, so this adapter does not use resume as a setting setter.

Inference is scheduled against actual active ownership/uncertainty. No token reservation or usage-triggered cancellation exists. Retain reported `tokenUsage.last` as provisional provider/client telemetry; cumulative session totals are not per-turn usage and absent usage remains null. Actual provider quota/capacity errors stay errors. Paused/disabled sources cannot apply configuration turns. Timeouts/disconnections retain unresolved intent and block fresh operation IDs; inspect and reconcile, never blindly resend.

## Explicit unmanaged → managed transition

This flow runs only on an explicit user request, for one project. It creates only necessary recipients. Existing source chat/code remain preserved. A new leader requires `prepare --role leader --model EXACT` and coordination-only tasks; no model is inferred from null policy. Core implementation uses `gpt-6.1-sol`, support `gpt-6-luna`, advisor `gpt-6-astra`; advisor implementation is refused.

1. Register the actual source member and bind its exact live identity with `bind --member SOURCE --thread THREAD`. Registration/binding are provenance claims, not completed migration. Drain commands and resolve all uncertain operations. The actual source owner writes a stop ACK JSON containing `source` (exact thread ID), `controller`, `commands_drained: true`, and `execution_stopped: true`. For exclusively controlled owned test sources, `exclusive_dispatch: true` can attest the wrapper checkpoint instead. External stop remains an operator attestation; the adapter cannot stop another dispatcher.
2. Prepare a minimal JSON packet with `goal`, `decisions` (including rationale), `constraints`, `remaining_work`, and `permission_ceiling: {"sandbox":"read-only","publication":false}`. Include only necessary nonsecret content. Claimed ownership paths must be canonical files or directories; hashes preserve uncommitted contents without reading history/authentication. `prepare --handoff ID --source SOURCE --recipient NEW --role core --tasks TASK --packet FILE --owner-stop-ack FILE --explicit-user-request` pauses the source and records the packet/version/hash and file baseline in the same project record.
3. `create --handoff ID --effort EFFORT --cwd PROJECT` records creation intent before RPC, requests the exact role model, and reads live configuration. Unknown creation outcomes block duplicate creation. If no reliable official correlation can resolve a missing returned ID, stop for manual reconciliation; never guess by title or inspect private session files.
4. `deliver --handoff ID` sends the packet in a nonimplementation turn. A completed model response must contain its exact unique hash/nonce ACK. This proves packet receipt only. `transfer --handoff ID` rechecks both live statuses, packet revision, owner stop ACK and file hashes, then changes canonical task ownership and disables the source atomically under the existing project-record lock. A precommit failure keeps source canonical and both paused. A postcommit failure keeps recipient canonical and paused; never automatically roll back after possible recipient action.
5. Read the committed transfer receipt. The actual owner creates a **new** JSON ACK containing exactly `handoff`, `recipient`, `transfer_revision`, and `transfer_nonce`. `owner-ack --handoff ID --revision REV --evidence FILE` validates those values and postcommit freshness. This is an operator attestation of the committed transfer, distinct from the earlier model packet ACK.
6. `resume --handoff ID` requires that exact revision/owner ACK and matching fresh live settings. Obtain the normal current harness context ACK before any implementation turn. Verify the receiver, remaining work and permission ceiling. The adapter enables only its own managed dispatch; other clients remain outside enforcement.

All pending intents, transitions and ownership live in the same `.codex-team/state.json`. Packet/evidence artifacts can be separate files, referenced by hashes. Do not publish project packets, session IDs, local paths, authentication or private evidence with the reusable source. Installation/global application is a separate reviewed operation; this feature does not migrate every project or hot-reload existing sessions.

## Cross-tool source and bounded writing

Version 0.5.3 extends the same prepare/create/deliver/transfer/owner-ACK/resume lifecycle. It does not migrate a project on installation. The source chat is retained, and failed task states, reviews, artifacts and canonical history survive transfer. Transfer invalidates context ACKs and removes current owner-bound work-authority pointers; retained correction/diagnostic history grants no successor authority. Active/uncertain diagnostic work still blocks transfer.

For a source that belongs to a different supported tool/backend, pass `prepare --external-source SPEC.json --expected-revision REV` with the existing explicit user request flag. The spec contains `identity` (exact `host`, `transport`, `controller`, `thread`, `owned: false`) and `observation` (canonical evidence path). The observation is a narrow operator capture of `codex_app.read_thread`: exact `source_identity`, `tool: "codex_app.read_thread"`, `status: "idle"`, exact completed `turn`, `turn_status: "completed"`, and the actual relevant source-owner `final_text`. Do not copy private native session stores, auth logs or unrelated conversation history.

The actual owner stop ACK contains the same `source_identity`, `execution_stopped: true`, `commands_drained: true`, exact `stopped_turn`, current `project_revision`, original `permission_ceiling`, the observation file's `observation_sha256`, and an `owner_ack_quote` copied from that final text. The operator is responsible for verifying that the quote is the actual owner's explicit stopped/drained acknowledgement. A waiting/idle message, an unavailable source, or a leader's claim that another owner stopped does not supply this ACK. This boundary is recorded as operator attestation with supported-tool evidence; it is not live native model/provider verification or an OS lock. Never fabricate an owner ACK.

At transfer, supply `--external-observation NEW.json` from a fresh supported read captured after preparation. Preserve the original hashed observation separately. The current observation must show the same exact identity, stopped turn and actual stop quote, still idle/completed. A new turn, active/unknown source, changed checkpoint/evidence, changed project revision/task obligations, or changed file tree blocks transfer. Overlapping unresolved handoffs reject new operation IDs. There is no automatic native CLI read/resume fallback.

Ownership paths may remain canonical directories. Baselines hash each regular file's contents, modes and types, every directory including empty directories, and additions/deletions. They retain the original directory claim rather than expanding ownership into a broader parent. Claim roots and ancestors remain canonical non-links. Descendant symlinks are opaque inventory entries: exact logical path, link mode, literal readlink target and device/inode/ctime identity are retained; targets are never resolved, read or traversed. Relative or absolute targets must be lexically inside the original claim. Dangling, chained and cyclic contained links are retained as metadata only; lexical containment does not attest target existence or effective resolution. Every inventoried link is checked independently, so an escaping link used by another target is refused. Escapes, special files and private metadata trees are refused. Regular files are opened without following links, with nonblocking opens and pre/open/post descriptor identity checks; directory traversal uses held directory descriptors and checks replacement/addition/deletion races. A changed tree fails closed rather than reseeding the baseline. Packets include necessary task/decision/constraint snapshots and a hash/reference to retained canonical history; no private source file contents are copied for baseline hashing.

Read-only remains the default. An explicitly approved writing ceiling has exactly:

```json
{"sandbox":"workspace-write","publication":false,"writable_roots":["/approved/project/source"],"network_access":false,"approval_policy":"on-request","approvals_reviewer":"auto_review"}
```

Every writable root must equal an original transferred claim. The session cwd must equal an approved directory root because workspace-write implicitly makes cwd writable. A root containing canonical project state, private metadata or a symlink is refused. No additional temporary roots or network access are granted. If the existing claims offer no such directory, this adapter cannot create an implementation session for that scope; ownership transfer and the ability to implement remain separate. Narrow the approved claims through the normal project workflow instead of choosing a broader cwd.

Creation requests official workspace-write configuration and verifies the official response. Returned cwd must be exact/canonical; type, network exclusion, both temporary-directory exclusions, approval policy and reviewer must be explicit. Compare the effective union of cwd and the explicit returned `writableRoots` to the approved roots. An explicit empty list may represent the implicit cwd only; a missing list, extra root or omitted second root is rejected. Every controlled turn repeats the approved sandbox policy and review settings. Receipt/configuration-only turns are read-only. The client never grants unexpected permission/tool requests; command-specific approval can still refuse. These checks do not prove provider execution identity.

A live allowed write plus an actual adjacent denied write/tool result are needed to substantiate sandbox enforcement. Model agreement/refusal alone is insufficient. Requested Normal remains a per-turn `serviceTierForTurn: "default"` acceptance receipt, with no persistent `serviceTier` override and no claim of actual provider tier.

Creation stores a sanitized official returned thread identity and permission/settings receipt before post-create validation. On an unknown result, never create another recipient to hide uncertainty. If an exact ID was returned, explicit `reconcile-create --handoff ID --effort EXACT --cwd EXACT` may use only that same owned official ID via metadata-only `thread/resume` and fresh validation; it never calls thread/start. It cannot recover a server-side thread with no persisted rollout. Preserve the ID/failure and leave both sides paused when the official server cannot reload it. Unknown outcomes with no returned ID need manual correlation; do not guess by title. Contract changes still require a separate project adoption and fresh packet, not a silent rewrite of an in-flight handoff.

Version 0.5.6 merges creation `config` keys with profile `config` keys, retaining exact requested reasoning and unrelated keys. Approved creation policy replaces each colliding config value as a whole, including `sandbox_workspace_write`; nested stale sandbox values are not retained. A conflicting selected model or reasoning effort is refused before creation intent or RPC. The managed-run read-only creation path has no second config supplier and is unaffected.

Existing failed creations need state-specific recovery. `reconcile-create` retains its original `creation_pending` guard. For an `outcome_unknown` failure after `control_recipient` (phase `recipient_created`), use the separate `recover-paused` procedure below. Never rewrite the phase, rebind, re-register, create a duplicate or fabricate an ACK. A later `policy_refresh` advances project revision and makes the prepared packet stale; installation and settings repair alone do not update it.

When the authorized official endpoint exposes the current protocol, metadata-only `thread/read` with `{ "threadId": "EXACT_RETURNED_ID", "includeTurns": false }` can inspect the same identity without resume or history hydration. A missing/not-loaded result is unknown, not permission to clone. For a loaded idle thread at an owner-controlled safe boundary, current `thread/settings/update` accepts `{ "threadId": "EXACT_RETURNED_ID", "model": "EXACT_MODEL", "effort": "EXACT_EFFORT" }`. Validate model/effort against the complete official catalog first. Omit cwd, sandbox, approval and all unrelated fields; verify the same-ID settings notification retains exact cwd, sandbox, network/tmp exclusions, approval policy and reviewer against the original permission receipt. Omitted `serviceTier` preserves persistent tier. If clearing persistent tier is separately authorized, explicit `serviceTier: null` clears it; it does not attest Standard provider execution. The empty update response acknowledges queuing only: require the same-ID `thread/settings/updated` notification and fresh matching live metadata before claiming configured settings. Cold loading is a separately authorized protocol procedure; the loaded-session repair command below does not imply that a particular backend supports these methods. Missing endpoint, unsupported method, missing notification or mismatched readback leaves correction unverified. A settings correction alone does not change handoff state or grant execution. Normal on any later authorized turn still requires explicit `serviceTierForTurn: "default"`; neither settings nor acceptance attests provider execution. Do not substitute a configuration-check inference turn without separate owner authorization.

## Paused recipient repair and fresh packets

`recover-paused --handoff ID --request-id UNIQUE --effort EXACT --cwd EXACT --expected-revision REV --expected-state-sha256 SHA` (or `Controller.recover_paused_recipient`) repairs only the exact already registered, owned, unmanaged recipient from a retained `recipient_created` failure. It requires the original source and recipient paused, canonical source ownership, unchanged tasks/reviews/claims/permission ceiling, no packet receipt/transfer/owner/context ACK, and no active or uncertain work. Both raw canonical bytes and revision are compared before intent and again before the result commits. It validates the complete catalog, requires the same recipient already live/idle, and sends only model plus effort through `thread/settings/update`; missing loaded state stops without automatic resume or creation. The same-ID settings notification must retain the full original permission receipt (cwd, sandbox/roots/network/both temporary exclusions, approval policy/reviewer), and fresh metadata must match exact model/effort and live idle status. Unexpected backend turn/item activity, missing notification or drift remains uncertain. Queued acknowledgement is not verification. The original receipt, failure, history and registration remain; only configured expectation/observation and the predelivery phase are reconciled. Both sessions stay paused, recipient unmanaged, source canonical. No ownership, ACK, execution or provider-tier claim is granted.

The source owner must maintain the actual exclusive stopped-producer boundary. A supported cold reconnect may use the same explicit official backend/namespace after a process restart; a preserved PID is not required. `thread/resume {threadId: EXACT_RETURNED_ID, excludeTurns: true}` loads/rejoins the same thread, initializes runtime/config/listeners and may persist metadata. It is not a pure read, and `excludeTurns` suppresses response history rather than automatic work. Before any separately authorized load, official `thread/queue/list {threadId, limit: 1}` must explicitly show empty data and no continuation cursor, and `thread/goal/get {threadId}` must explicitly show no goal or a known non-active same-ID goal. Hold the exclusive owner boundary across preflight and load, then verify same ID, original permissions, live idle metadata and no observed activity. Unsupported, not-found/no-rollout, denied, missing or ambiguous replies stop without clone, guessed endpoint or fallback backend. The harness does not automatically perform this load; prefer the same long-lived authorized Controller connection for load/settings/repair. Settings-only operations do not start a model turn. Normal on a later authorized turn still needs explicit `serviceTierForTurn: "default"`; persistent tier is omitted/preserved and provider execution remains unavailable.

After explicit current-contract adoption, `refresh-packet --handoff ID --request-id UNIQUE --expected-packet-hash HASH --owner-stop-ack FILE --external-observation FILE --expected-revision REV --expected-state-sha256 SHA` (or `Controller.refresh_packet`) replaces only a stale, undelivered packet under the same unchanged owner/tasks/reviews/claims/content/ceiling/recipient identity. It archives the exact old packet, hash, nonce, checkpoint, provenance and failure in `packet_versions`, creates a fresh version/hash/nonce/current revision and retains original management consistency checks. There is no management-tree reseeding or new writable scope. Capture the two fresh source evidence files **outside all retained claim baselines**, so new files do not alter inventoried product or management trees. They must postdate the relevant contract/revision boundary and bind exact source identity, actual stopped completed turn/owner quote, current revision, original ceiling and observation hash. External-source evidence retains its existing schema. An owned-source checkpoint contains `source`, `controller`, `commands_drained: true`, `execution_stopped: true`, `actual_stop_turn`, `actual_owner_text`, `project_revision`, `permission_ceiling` and `observation_sha256`; its supported `codex_app.read_thread` observation has exact `source_identity`, idle/completed stopped turn and the actual owner text in `final_text`. Owned provenance stays owned; no external identity is invented. Original owner evidence remains immutable. Refreshed owned-source evidence is also revalidated at transfer with a fresh supported observation of the same stopped turn and actual owner text.

Repeated identical request IDs return their committed historical receipt without resending or changing nonce/history; changed arguments are rejected. Durable pending/unknown settings intents block new recovery IDs and policy adoption. A write failure after commit is resolved by the identical request receipt, not by a new operation. Product/content or canonical-byte drift is retained and blocks commit. A refreshed packet requires a **new actual delivery and genuine hash/nonce ACK** before the normal transfer, fresh postcommit owner ACK, resume and current-context ACK. Synthetic lifecycle fixtures prove protocol behavior only; they are never actual participant ACKs. Installing these commands performs none of those project transitions.

## Management directory ownership

Version 0.5.4 can retain an ownership claim for the **exact canonical `.codex-team` directory containing this Controller's state file**. This administrative ownership is separate from the original product writing ceiling: `.codex-team`, its state file, and a parent containing canonical state are never recipient writable roots. Product directory/file claims remain strict content/type/mode baselines.

The management tree is fully inventoried. Ordinary files, retained FAIL evidence, lock contents/mode, empty directories, additions/deletions and symlinks remain checked. Only the exact canonical state file may change through the existing locked management transitions. A digest covers the complete canonical state and history, excluding only its own digest field. Before each transition the adapter checks that digest and the exact canonical serialized bytes; after the existing apply/history mutations it computes the next commitment from the in-memory result under the same lock, checks the original state bytes still match, and rechecks both management and product baselines. It never repairs/reseeds a mismatch from a fresh file read. Same-revision edits to controls, profiles or history, including removal or premature retirement of management metadata, fail closed. This is consistency/CAS protection, not OS authentication or protection against an actor who rewrites state and recomputes its commitments.

A fresh source observation file may be added within the management directory only by its existing `control_transfer` validation. A new postcommit owner ACK file may be added only by its existing `control_owner_ack` validation. Each must have the exact canonical path, correct phase and validated content/hash; an existing retained file cannot be overwritten. No other management files or directories are ignored. Keep these evidence files directly in the claimed management directory or in an already inventoried subdirectory. Transfer reads recipient configuration without an intermediate state write, so the explicitly supplied fresh observation can be admitted by the atomic transfer itself.

The original handoff packet/baseline/hash is immutable. A separate protected management continuation record tracks authorized state/evidence changes until ownership is resumed and the receiver's actual current harness context ACK commits. An early ACK cannot retire the guard. Normal role packets omit operational guard bookkeeping, so the guard's own updates do not invalidate that ACK; actual decisions, constraints and task obligations remain in the context digest. After that completed handoff, normal project work can continue without a permanent directory freeze. Existing task states, FAIL history, claims and successor-authority requirements are preserved. No project adoption, source stop ACK, recipient creation, permission expansion or actual migration occurs on installation.

Version 0.5.5 adds a pure `external_handoff.preflight(paths, state_path=...)` compatibility check. It inventories all requested claims, returns file/directory/link/missing counts and per-claim failures, and dry-runs the exact management guard without creating a lock, session, packet, control record or writing authority. It reports hashes and metadata, never target contents or private file contents. Installation remains separate from owner checkpoint, contract adoption and real handoff.
