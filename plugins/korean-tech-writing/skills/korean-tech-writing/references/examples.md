# 고치기 전·후 예시

아래 예시는 규칙을 보이려고 지어낸 문장이다. 특정 제품의 실제 동작을 뜻하지 않는다. "근거 조건" 열은 고친 문장을 쓰려면 자료에 무엇이 있어야 하는지를 적는다.

## 1회차: 요구의 강도

| 고치기 전 | 고친 문장 | 근거 조건 |
|---|---|---|
| 로그에 개인정보를 남기지 않도록 주의해 주세요. | 앱은 로그에 이메일과 전화번호를 기록해서는 안 된다. | 금지 대상 항목이 자료에 있어야 한다. 없으면 "금지 대상 확인 필요". |
| 가능하면 배치 크기는 100 이하로 합니다. | 호출자가 배치 크기를 100 이하로 하기를 권장한다. 예외: 백필 작업은 1,000까지 보내도 된다. | 예외 조건이 자료에 있어야 한다. 없으면 "예외 확인 필요". |
| 서버는 재시도할 수 있다. (허용 뜻) | 서버는 실패한 요청을 다시 시도해도 된다. | 허용인지 능력인지 원문 맥락으로 판단한다. |
| 이 함수는 반드시 빈 배열을 반환해야 합니다. (동작 설명) | 이 함수는 결과가 없으면 빈 배열을 반환한다. | 구현을 설명하는 문서라면 요구 형태를 쓰지 않는다. |

## 2회차: 문장

| 고치기 전 | 고친 문장 |
|---|---|
| 푸시 알림 토큰 등록 실패 시 재처리 로직이 수행됩니다. | 푸시 알림 토큰을 등록하지 못하면 앱이 30초 뒤에 다시 등록한다. (30초는 자료에 있을 때만 쓴다.) |
| 설정 파일을 수정하고 서버를 재시작하고 로그를 확인합니다. | 1. `config.yaml`을 고친다.<br>2. 서버를 다시 시작한다.<br>3. 로그에 `ready`가 나오는지 확인한다. |
| 마이그레이션을 실행합니다. 이전 데이터가 삭제될 수 있으니 주의하세요. | 경고: 실행하기 전에 데이터베이스를 백업한다. 마이그레이션은 `legacy_*` 테이블을 지우고, 지운 테이블은 되돌릴 수 없다.<br>1. 마이그레이션을 실행한다. |
| 캐시를 통해 응답 속도 향상이 가능합니다. | 응답을 캐시하면 같은 요청의 두 번째 응답이 빨라진다. (측정값이 있으면 대상·환경·횟수와 함께 쓴다.) |

## 3회차: 사실과 확인 수준

| 고치기 전 | 고친 문장 |
|---|---|
| 수정 완료했고 정상 동작합니다. | 조건문을 고쳤다. Debug 빌드가 성공했다. 실행해서 확인하지는 않았다. |
| 성능이 2배 좋아졌습니다. | M3 MacBook Air에서 `bench-sync`를 5회 실행했다. 평균 시간이 820ms에서 410ms로 줄었다. |
| 이 변경으로 크래시가 해결됩니다. | 크래시 로그의 스택이 가리키는 강제 언래핑을 제거했다. 같은 크래시가 다시 나는지는 확인하지 않았다. |
