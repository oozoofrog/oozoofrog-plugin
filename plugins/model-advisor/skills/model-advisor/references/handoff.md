# 넘기기 절차

## 1. 지시문 작성

받는 쪽은 이 대화를 보지 못한다. 지시문만 읽고 바로 시작할 수 있게 쓴다.

지시문은 영어로 쓴다. 사용자가 한국어로 지시했더라도 영어로 옮겨 전달하고, 코드·경로·사용자에게 보일 문구는 원문 그대로 인용한다. 받는 쪽이 영어로 작업하고 영어로 보고하게 한다. 사용자에게 하는 답만 사용자의 언어로 한다. 서브에이전트의 보고는 이 세션이 사용자의 언어로 옮겨 전하고, 사용자가 직접 대화할 백그라운드 세션에는 "작업은 영어로 하되 사용자에게는 사용자의 언어로 답하라"는 문장을 지시문에 넣는다.

- **목표**: 무엇을 끝내면 되는지 한두 문장
- **완료 기준**: 통과해야 할 테스트·빌드·확인 방법
- **이미 확인한 것**: 알아낸 사실, 배제한 가설, 사용자가 이미 내린 결정
- **볼 곳**: 관련 파일·문서 경로. 내용을 옮겨 적지 않고 경로로 가리킨다. 이 브랜치에 `_context/handoff/<브랜치>.md` 인계 문서가 있으면 먼저 읽으라고 적는다.
- **범위**: 하지 말 것(커밋·푸시 금지, 특정 파일 금지 등)과 사용자에게 물어야 할 결정
- **보고**: 끝나면 무엇을 남길지(바뀐 파일, 실행한 검증, 남은 위험)

사용자 지침 파일(CLAUDE.md, AGENTS.md)은 새 세션도 스스로 읽으므로 반복하지 않는다. 사용자 이메일 같은 개인 정보는 넣지 않는다.

## 2-A. 서브에이전트

Agent 도구를 다음처럼 부른다.

- `model`: `haiku`, `sonnet`, `opus`, `fable` 중 추천 모델
- `effort`: 추천 effort(이 스킬이 지정을 지시하므로 넣는다). 모델 기본값을 추천했으면 생략한다.
- `subagent_type`: 읽기만 하면 `Explore`, 수정이 필요하면 `general-purpose`. `fork`는 모델 지정이 무시되므로 쓰지 않는다.
- `prompt`: 1의 지시문
- 현재 세션이 같은 파일을 고치고 있으면 `isolation: "worktree"`를 고려한다.

결과가 돌아오면 그대로 믿지 않고 핵심 주장 하나 이상을 직접 확인한 뒤 사용자에게 전한다.

## 2-B. 백그라운드 세션

1. 지시문을 스크래치패드 디렉터리에 `handoff-<이름>.md`로 쓴다.
2. 작업할 프로젝트 루트에서 실행한다.

```sh
claude --bg --model <별칭> --effort <effort> -n "<짧은 이름>" "$(cat <지시문 파일 절대 경로>)"
```

- 별칭: `haiku`, `sonnet`, `opus`, `fable`. 정확한 버전이 필요하면 `claude-sonnet-5-5` 같은 전체 ID를 쓴다.
- 이름: 작업을 알아볼 수 있게 짧게(예: `fix-login-sonnet`). `claude attach`에 이름 일부를 쓸 수 있다.
- 권한: 새 세션은 사용자 기본 권한 모드를 따른다. `--permission-mode`, `--dangerously-skip-permissions`를 임의로 붙이지 않는다.
- 현재 세션과 같은 파일을 동시에 고칠 위험이 있으면 `-w <이름>`으로 별도 worktree에서 띄운다.
- "Workspace not trusted"로 실패하면 그 폴더를 아직 신뢰하지 않은 것이다. 사용자에게 그 폴더에서 `claude`를 한 번 실행해 신뢰를 승인해 달라고 안내한다. 다른 폴더로 우회하지 않는다.

3. 출력의 `backgrounded · <id> · <이름>` 줄에서 id를 얻는다.
4. 몇 초 뒤 시작을 확인한다.

```sh
claude logs <id> | grep -o '[A-Z][a-z]* [0-9.]* with [a-z]* effort' | head -1
claude agents --json
```

첫 줄이 추천한 모델·effort와 다르면 `claude stop <id>`로 멈추고 다시 띄운다. `claude agents --json`의 `state`로 실행 중인지 끝났는지 본다.

5. 넘긴 뒤 현재 세션은 그 세션이 맡은 파일을 고치지 않는다.

## 2-C. 현재 세션 전환 안내

직접 바꿀 수 없으므로 사용자에게 순서만 안내한다: `/compact` → `/model <모델>` → `/effort <effort>`. 끊김 지점(테스트 통과, 커밋 직후 등)에서 바꾸라고 덧붙인다.
