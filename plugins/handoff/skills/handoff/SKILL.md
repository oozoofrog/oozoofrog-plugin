# 인계 문서

새 세션은 이 문서만 보고 일을 이어받는다. 그래서 틀린 내용이 남아 있으면 새 세션이 그대로 따른다. 쓰는 것만큼 지우고 고치는 것이 중요하다.

Claude Code에서는 Plugin 훅이 `/clear` 뒤에는 문서 전체를, 새로 시작하거나 `--resume`일 때는 목표와 다음 할 일만 넣어 준다. 압축 뒤에는 압축 전에 쓴 문서 대신 위치만 알린다. 오래됐거나(14일, 커밋 30개 초과) 작성 당시 커밋과 기록이 갈라진 문서도 위치만 알린다. 훅이 없는 환경에서는 새 세션에서 문서를 직접 읽는다.

아래 명령의 `<skill-dir>`은 이 스킬을 불러올 때 표시되는 기준 폴더(이 SKILL.md가 있는 폴더)다.

## 쓰는 순서

1. 준비: 프로젝트 안에서 실행한다.
   ```bash
   python3 -I -B "<skill-dir>/scripts/ctx.py" prepare
   ```
   - 결과 JSON의 `handoff_path`에 쓴다. 다른 세션이 쓴 기존 문서는 `archived` 경로에 보관돼 있다. 이 세션이 쓴 문서를 다시 쓸 때는 보관하지 않는다.
   - `pruned`는 이번에 치운 문서다: 끝난 문서·사라진 브랜치·detached 상태의 문서는 `sessions/`로 옮기고, 오래된 보관본은 지운다.
   - `stale`이 비어 있지 않으면 기존 문서가 지금 코드와 맞지 않을 수 있다. 내용을 현재 코드와 대조한 뒤에만 이어받는다.
   - `warning`이 있으면 다른 세션이 쓰던 문서다. 그 내용을 읽고 합친 뒤 쓴다.
   - `ok: false`면 이유를 사용자에게 알린다. git 저장소가 아닌 폴더에서 사용자가 원하면 `--allow-non-git`을 붙인다(홈 폴더는 거부된다).
2. `existing`이 true면 기존 문서를 읽고 **모든 항목을 하나씩 처리한다.** 그대로 복사하지 않는다.
   - 끝난 일: 지운다. 다음 세션의 판단에 필요한 결과만 "끝낸 일"에 남긴다.
   - 확인된 가정: "확인 안 된 것"에서 빼고 근거와 함께 사실로 쓴다.
   - 더 이상 해당 없는 항목(방향이 바뀜, 틀린 것으로 밝혀짐): 지운다.
   - 아직 확인 못 한 항목: `(처음 기록 YYYY-MM-DD)`를 붙여 유지한다. 날짜가 오래된 항목은 지금 확인하거나 버린다.
   - 오래 남길 결정: 아래 "오래 남길 내용은 원래 자리로"에 따라 옮기고 인계 문서에서는 뺀다.
3. 아래 형식으로 `handoff_path`에 쓴다. frontmatter 값은 prepare 결과(`branch`, `head`, `session_id`, `now`)를 그대로 쓴다.
4. 검사하고, 통과할 때까지 고친다. 검사는 현재 브랜치·HEAD·세션과 맞는지, 체크된 항목(`- [x]`)이 남았는지, "끝낸 일"이 8개를 넘는지도 본다.
   ```bash
   python3 -I -B "<skill-dir>/scripts/ctx.py" validate <handoff_path>
   ```
5. 사용자에게 한 줄로 알린다: 문서 경로와 "`/clear` 하면 이 문서로 이어집니다".

## 작업이 끝났을 때

1. 문서에 남은 결정과 확인된 사실 중 오래 남길 것을 원래 자리로 옮긴다. 옮기지 않으면 보관 폴더에 묻힌다.
2. 끝낸다. 문서는 `sessions/`로 옮겨지고 새 세션에 더는 들어가지 않는다.
   ```bash
   python3 -I -B "<skill-dir>/scripts/ctx.py" set-status done
   ```

## 형식

```markdown
---
status: active
branch: <prepare.branch>
head: <prepare.head>
updated: <prepare.now>
session_id: <prepare.session_id>
goal: <한 문장 목표>
---

# 인계: <작업 이름>

이전 인계: [[<archived 파일 이름에서 .md를 뺀 것>]]   ← archived가 없으면 이 줄을 뺀다

## 목표와 완료 기준
## 끝낸 일
## 진행 중
## 결정과 이유
## 확인 안 된 것
## 다음 할 일
## 핵심 파일
```

## 쓰는 기준

- 다음 세션이 판단하고 행동하는 데 필요한 것만 쓴다. 대화 내용을 옮기거나 진행 과정을 서술하지 않는다.
- 사실에는 근거를 붙인다: `파일:줄`, 실행한 명령과 결과(통과/실패 수), 커밋. 검증하지 못한 것은 "확인 안 된 것"에 둔다.
- "다음 할 일"은 바로 실행할 수 있는 단위로, 우선순위 순서로 쓴다. 이 섹션이 비면 검사에서 실패한다.
- 길이는 prepare 결과의 `limit_chars` 이하. 넘으면 끝낸 일을 줄이고 세부는 파일 경로로 대신한다.
- 비밀값(토큰, 키, 비밀번호, 개인 정보)은 쓰지 않는다. 도구 출력에서 옮겨 적을 때 특히 확인한다.

## 오래 남길 내용은 원래 자리로

인계 문서는 이 작업이 끝나면 의미가 없어지는 상태만 담는다. 작업 중 오래 남길 내용이 생기면 원래 자리로 보낸다.

| 내용 | 자리 | 방법 |
| --- | --- | --- |
| 사용자 선호, 여러 프로젝트에 걸친 사실 | 자동 메모리 | 직접 저장 |
| 이 프로젝트의 설계 결정과 이유 | `.dual-brain/MEMORY.md` | 파일이 이미 있으면 그 형식(Hot/Warm/Cold)대로 추가, 없으면 사용자에게 제안 |
| Claude가 지켜야 할 프로젝트 지시 | 프로젝트 CLAUDE.md | 사용자에게 제안만 한다 |

## 참고

- 문맥 사용량 경고 기준은 40만 토큰, 이후 15만 토큰마다 한 번 더 알린다. 환경 변수 `HANDOFF_TOKENS`, `HANDOFF_TOKENS_STEP`으로 바꾼다.
- T3 Code 위임 스레드(`T3CODE_THREAD_ID`가 `thread:delegated-task:`로 시작)에서는 경고하지 않는다. 이어받을 사람이 없어 인계 문서 작성 비용만 들기 때문이다.
- `_context/`는 기본으로 git에 올라가지 않는다(`_context/.gitignore`가 `*`). 커밋하려면 그 파일을 고친다. git이 추적하는 인계 문서는 남의 저장소에서 온 지시가 섞일 수 있어 자동으로 넣지 않고 위치만 알린다.
- 압축이 일어나면 압축 요약이 `_context/sessions/`에 저장된다.
- 자동 정리 기준(환경 변수로 변경):
  - 오래된 문서 판정: 14일(`HANDOFF_STALE_DAYS`), 커밋 30개(`HANDOFF_STALE_COMMITS`)
  - 압축 요약 삭제: 30일(`HANDOFF_KEEP_COMPACT_DAYS`)
  - 보관한 인계 문서 삭제: 90일(`HANDOFF_KEEP_ARCHIVE_DAYS`)
  - `sessions/`에 직접 둔 다른 노트는 지우지 않는다.
- 현재 위치·상태·오래됨 확인: `ctx.py status`. 정리만 따로 실행: `ctx.py prune`.
