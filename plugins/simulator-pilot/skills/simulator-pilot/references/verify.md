# 변경 확인

"고친 것이 앱에서 실제로 되는지"를 확인하는 순서다.

1. **확인할 동작을 한 문장으로 정한다.** 예: "다크 모드에서 채팅방 말풍선 배경이 어둡게 보인다." 정할 수 없으면 사용자에게 묻는다. 변경 전과 후가 달라지는 입력·화면을 고른다.
2. **빌드**: 프로젝트의 빌드 지침로 빌드한다(스킴은 그 스킬이 묻는다). 빌드가 끝나면 `sim-pilot launch --udid <UDID> --scheme "<스킴>" --reinstall`로 방금 빌드한 앱을 설치하고 실행한다. `--reinstall`이 없으면 이미 설치된 예전 앱이 그대로 실행된다.
3. **준비**: 필요한 테스트 데이터·설정을 넣는다([test-data.md](test-data.md)). 계정이 필요하면 로그인 상태를 먼저 확인하고, 없으면 프로젝트의 계정 준비 절차를 확인한다.
4. **이동**: [drive.md](drive.md) 순서로 화면까지 간다.
5. **증거**: `screenshot`을 찍는다. 로그가 근거면 `sim-pilot logs`로 해당 줄을 모은다.
6. **판정**:
   - 화면 판정에 mac-cu `decide`를 사용할 수 있다. 화면 자료가 OpenAI에 전송되므로 사용자 승인을 확인한다.
   - 모델 확률은 보정되지 않았으므로 스크린샷이나 접근성 정보로 결과를 직접 확인한다.
   - 텍스트·값으로 판정할 수 있으면 `describe`의 라벨·value를 근거로 쓴다.
7. **보고**: 기기·OS·스킴, 거친 화면 순서, 스크린샷(또는 저장 경로), 판정과 근거. 확인하지 못한 부분은 따로 적는다.
