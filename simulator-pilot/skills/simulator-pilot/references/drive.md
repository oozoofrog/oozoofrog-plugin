# 화면 조작

mac-cu `simulator` 도구로 화면을 읽고 조작한다. 시뮬레이터 창이 뒤에 있거나 닫혀 있어도 된다. 좌표는 포인트이며 `screenshot` 이미지의 픽셀과 같다.

## 순서

1. **읽기**: `describe`로 앞에 있는 앱의 요소를 본다. 줄마다 역할, 라벨, `id`, `value`, 가운데 좌표, 크기가 나온다.
   - 찾는 것이 정해져 있으면 `query`를 준다: `{"action": "describe", "query": "일반"}`
   - 웹뷰(WKWebView) 안의 내용은 트리에 나오지 않는다(예: 카카오계정 가입·약관 화면). 요소가 거의 없으면 `screenshot` 좌표로 조작한다.
   - `[partly off screen]`, `[off screen]` 표시가 붙은 요소는 앱이 떠난 이전 화면의 것일 수 있다. 누르지 않는다.
2. **누르기**: 이름이 있으면 `tap`에 `target`(라벨·id·value)을 준다. 화면에 완전히 들어온 요소가 먼저 고려되고, 나타날 때까지 `timeout`초(기본 5) 기다린다.
   - `{"action": "tap", "target": "com.apple.settings.general"}` — id가 라벨보다 안정적이다.
   - 이름이 없는 요소(커스텀 그리기, 접근성 라벨이 없는 버튼)는 `describe`나 `screenshot`으로 좌표를 정해 `x`, `y`로 누른다.
3. **기다리기**: 화면 전환 뒤에는 다음 화면의 요소를 `wait`로 기다린다: `{"action": "wait", "target": "정보", "timeout": 10}`
4. **확인**: 결과를 `describe`(텍스트로 충분할 때) 또는 `screenshot`(색·배치·이미지를 봐야 할 때)으로 확인한다.

## 동작별 메모

| 동작 | 호출 | 메모 |
|---|---|---|
| 길게 누르기 | `tap` + `seconds` | 예: 1.0 |
| 스크롤 | `swipe` (`x`,`y` → `to_x`,`to_y`) | 아래 내용을 보려면 손가락을 위로: y가 큰 곳에서 작은 곳으로 |
| 되돌아가기 | 왼쪽 가장자리에서 오른쪽으로 `swipe`, 또는 뒤로 버튼 `tap target` | |
| 여러 손가락·복합 동작 | `gesture` + `frames` | 최대 세 손가락의 탭·유지·이동·해제를 독립적으로 지정한다. 아래 예시 참고 |
| 텍스트 | 칸을 `tap` → `type` | 영문·숫자, 키보드가 한국어면 한글 두벌식으로 친다 |
| 섞인 텍스트·이모지 | `paste` → "붙여넣기 허용" `tap target` | 허용 대화상자가 뜬다 |
| 키 | `key` (`Return`, `cmd+a`, `delete`) | 포커스된 칸에 간다 |
| 홈·잠금 | `button` (`home`, `lock`) | |

키보드 언어 바꾸기, 붙여넣기 허용, 화면이 둘인 기기(iPhone Duo) 같은 세부는 mac-computer-use 스킬의 "iOS Simulator: simulator" 절을 따른다.

## 세 손가락까지의 제스처 (mac-cu 1.21.0)

`gesture`는 Xcode의 UniversalHID 터치스크린 보고서를 직접 보낸다. 외부 자동화 도구나 테스트 러너를 설치하지 않는다. 손가락별 ID를 유지하므로 세 손가락 스와이프, 한 손가락 고정과 다른 손가락 이동, 핀치·회전·이동의 조합, 반복 탭과 길게 누른 뒤 드래그를 같은 방식으로 표현한다.

```json
{"action":"gesture","device":"<UDID>","frames":[
  {"time":0,"touches":[{"id":1,"phase":"down","x":100,"y":400},{"id":2,"phase":"down","x":200,"y":400},{"id":3,"phase":"down","x":300,"y":400}]},
  {"time":0.5,"touches":[{"id":1,"phase":"move","x":100,"y":250},{"id":2,"phase":"move","x":200,"y":250},{"id":3,"phase":"move","x":300,"y":250}]},
  {"time":0.6,"touches":[{"id":1,"phase":"up","x":100,"y":250},{"id":2,"phase":"up","x":200,"y":250},{"id":3,"phase":"up","x":300,"y":250}]}
]}
```

- `time`은 시작으로부터의 초이며 0~10초 범위에서 증가한다. 최대 10초, 1,201프레임이다. 같은 프레임의 접점 변경은 한 보고서로 보낸다. `touches: []`는 누른 위치를 유지하는 시점이다.
- ID는 1~3이다. `down`부터 `up`까지 같은 ID를 사용하고, 생략한 활성 손가락은 그 위치를 계속 누른다. `move` 사이의 경로는 60Hz로 선형 보간하므로 곡선은 중간 점들을 준다. 마지막에는 모든 손가락을 올린다.
- 좌표는 현재 화면의 포인트다. 실행 중 기기를 돌리거나 접지 않는다. 실패·중단 시 활성 접점을 해제한다.
- 전송과 앱의 인식 결과를 구분한다. 세 손가락 편집 제스처처럼 OS가 처리하는 동작도 있으므로 `describe`·`screenshot`으로 결과를 확인한다. `rotate`는 기기 자세 변경이고, 손가락 회전은 `gesture`로 한다.
- `sim-pilot caps`의 제스처 항목은 전송 서비스의 존재를 확인한다. mac-cu 버전과 앱 인식 여부까지 검사하지는 않는다.

## iPhone Duo

mac-cu 1.15.0부터 `tap`, `swipe`, `describe`, `wait`는 **지금 켜진 화면**을 쓴다. 접었을 때는 바깥 화면(`LCD`), 펼쳤을 때는 안쪽 화면(`LCD-1`)이다.

- 좌표는 그 화면이 보이는 방향 그대로다. 안쪽 화면이 가로로 켜져 있으면 951×669 포인트이고, `screenshot`에서 `(on: ...)`이 붙은 그림의 픽셀과 같다.
- `screenshot`은 화면마다 한 장씩 준다. 꺼진 화면은 검다. `guides` 상자는 켜진 화면에 그려진다.
- 홈 버튼(`button home`)은 트리가 이전 앱을 벗어날 때까지 기다리고 앞 앱 이름을 알려 준다(mac-cu 1.16.1). 같은 앱 안에서 화면이 바뀐 뒤(제어 센터 편집 모드를 닫은 뒤 등)에는 트리가 몇 초 늦을 수 있으니 `wait`로 다음 화면의 요소를 기다린다.
- 트리에 없는 것: 다른 프로세스가 그리는 공유 시트 내용, Safari·WKWebView의 웹 페이지 내용(DOM은 mac-cu `webinspector`). 이런 요소는 스크린샷 픽셀로 누른다. 권한 요청 알림·키보드·제어 센터·잠금 화면은 트리에 있고 좌표도 맞다.

### 접기·펴기·회전 (mac-cu 1.16.0)

| 하려는 것 | `simulator` 동작 | 결과 확인 |
|---|---|---|
| 접기 | `hinge` `state: "closed"` (0°) | 답의 `it reads 0.0°`와 켜진 화면 `LCD` |
| 펴기 | `hinge` `state: "open"` (180°) | `LCD-1`이 켜짐 |
| 반쯤 펴기 | `hinge` `degrees: 0~180` | 켜지는 화면은 오던 방향에 따라 다르다(실측: 펼 때 90°는 바깥·110°는 안쪽, 접을 때 75°는 안쪽·60°는 바깥) |
| 지금 각도 읽기 | `hinge` (값 없이) | |
| 돌리기 | `rotate` `orientation: "landscape-left"` 등 | 답의 `rot0`·`rot90`·`rot270` |

- 접거나 돌린 뒤의 `tap`·`describe`·`screenshot`은 바뀐 화면과 방향을 따른다. 따로 기다릴 필요는 없다.
- `hinge`는 사이 각도를 연속으로 지나가며 접고 편다(mac-cu 1.20.0). 각도를 한 번에 건너뛰면 SpringBoard가 화면을 바꾸지 않고, 그 뒤로는 힌지를 아예 따르지 않는다(mac-cu 1.19 이하나 다른 도구에서 생김). 답에 `did not come on`이 나오면 `button` `lock`을 두 번 누르고 다시 보낸다.
- 앱은 지원하는 방향으로만 돈다. 홈 화면(SpringBoard)은 iPhone에서 세로로만 있다.
- 실험이 끝나면 처음 상태로 되돌린다. 부팅 직후 Duo는 접힌 상태다.
- 독립 확인: `xcrun devicectl device info displays --device <UDID>`의 `active`와 `currentOrientation`.

mac-cu 1.14 이하에서는 안쪽 화면에 탭이 닿지 않고, 1.15 이하에는 `hinge`·`rotate`가 없다. `tap` 결과에 `on LCD-1`이 붙지 않거나 `hinge`가 없다고 나오면 mac-computer-use 플러그인을 업데이트하고 setup.py를 다시 실행하라고 안내한다.

## 접근성으로 누르기·Watch 크라운 (mac-cu 1.18.0)

- `press` `target: "<라벨 또는 id>"`: 터치 대신 접근성 Press로 누른다. 좌표·화면·회전과 상관없고, 다른 뷰에 가려진 요소도 눌린다(설정 앱 아래 검색 칸에 가려진 `스크린 타임` 행으로 확인). 목록이 아직 만들지 않은 화면 밖 칸은 트리에 없으니 먼저 스크롤한다.
- `crown` `amount: 120`: Apple Watch의 디지털 크라운을 돌린다. 양수는 내용을 아래로, 음수는 위로 스크롤한다. Device Hub에서 크라운 위에 커서를 두고 휠을 굴리는 것과 같은 신호다.

## 뷰 계층과 레이아웃 제약 (mac-cu 1.17.0)

`simulator` `views`는 Xcode 뷰 디버거처럼 앱의 UIView 계층(클래스, 상위 뷰 기준 frame, hidden, alpha, 접근성 id, 텍스트)과 각 뷰의 활성 Auto Layout 제약을 텍스트로 준다.

- `app`에 번들 ID(기본은 앞 앱), `query`에 클래스 이름·id·라벨 일부를 준다. 예: `{"action": "views", "app": "com.kakao.iPart.sandbox.Talk", "query": "ChatListCollectionViewCell"}`
- lldb가 앱에 붙었다 떨어지는 동안 **앱이 약 20초 멈춘다.** 사용자가 화면을 보고 있으면 먼저 알린다.
- 접근성 트리(`describe`)에 없는 장식 뷰, 숨은 뷰, 제약 충돌 원인을 볼 때 쓴다. 누를 요소를 찾을 때는 `describe`가 빠르다.

## 화면을 따로 띄워 보기 (mac-cu 1.20.0)

사용자가 시뮬레이터 화면을 보고 싶어 하면 `simulator` `window`로 mac-cu 창을 연다. Device Hub나 Simulator 앱을 열지 않아도 된다.

- 시뮬레이터가 그리는 화면을 그대로 실시간으로 보여 준다. 켜진 화면만 보이고, 접기·펴기·회전을 2초 안에 따라간다(iPhone Duo는 바깥↔안쪽 화면으로 바뀜).
- 창 크기는 Mac 화면에 맞게 줄이고, Apple Watch처럼 작은 화면은 키운다. 답에 시뮬레이터 포인트와 Mac에서 보이는 크기가 나온다.
- 사용자는 창에서 시뮬레이터를 직접 쓸 수 있다.
  | Mac에서 | 시뮬레이터에서 |
  |---|---|
  | 클릭·드래그 | 탭·스와이프·길게 누르기 |
  | Option+드래그 | 두 손가락(가운데를 기준으로 대칭: 핀치·회전) |
  | 키보드 | 같은 자리의 키. 글자는 시뮬레이터 키보드 설정을 따른다(한국어면 두벌식) |
  | 스크롤 | 손가락 끌기(Apple Watch는 디지털 크라운) |
  | ⇧⌘H / ⇧⌘L | 홈 / 잠금 버튼 |
- 에이전트는 창을 `act`로 누르지 않는다(mac-cu가 자기 창은 거절한다). 조작은 `simulator`의 `tap`·`swipe` 등으로 한다.
- 다시 부르면 창을 앞으로 가져오고, `close: true`로 닫는다. 시뮬레이터가 꺼지면 창도 닫힌다.

## 주의

- 한 번에 많이 누르지 않는다. 화면이 바뀌는 동작 뒤에는 `wait`나 `describe`로 다음 화면을 확인하고 이어 간다.
- 결제·전송·삭제·계정 변경처럼 되돌리기 어려운 버튼은 사용자가 요청한 것일 때만 누른다.
- 비밀번호는 도구 인자로 넘기지 않는다. 사용자가 입력하게 하거나, 프로젝트가 정한 자격 증명 전달 절차를 따른다.
